CPU 與計算機組織

CPU 是計算機的大腦——每秒可執行數十億次指令。本章拆解 von Neumann 架構、Fetch-Decode-Execute 週期、管線化、與 RISC/CISC、CPU/GPU 的設計權衡。

The CPU is the computer's brain — billions of instructions per second. This chapter unpacks the von Neumann model, fetch-decode-execute, pipelining, and the RISC/CISC and CPU/GPU trade-offs.

概覽

CPU 是怎麼運作的？

中央處理單元 (Central Processing Unit, CPU) 是執行程式指令的核心晶片。一顆 2026 年的桌面 CPU 內含數百億顆電晶體，組成數十個核心，每秒可完成上兆 (10¹²) 次基本運算。

無論是手機、伺服器、汽車 ECU 還是 AI 推論加速器，內部運作都遵循同一個套路：取指 (Fetch) → 解碼 (Decode) → 執行 (Execute) → 寫回 (Writeback)，俗稱「機器週期」。

The Central Processing Unit (CPU) is the chip that executes program instructions. A 2026 desktop CPU contains tens of billions of transistors organized into dozens of cores, performing trillions (10¹²) of basic operations per second.

Whether it's a phone, server, car ECU, or AI accelerator, the routine is the same: Fetch → Decode → Execute → Writeback — the "machine cycle."

💡
核心觀念：CPU 並不「理解」程式，它只是不斷讀取記憶體裡的 0/1，按照硬體電路的規則動作。所謂「智慧」來自程式設計師寫的指令序列。 Core idea: A CPU does not "understand" programs — it just reads 0/1 from memory and reacts per hardware rules. The "intelligence" comes from the programmer's instruction sequence.

實務上，現代 CPU 是「修改型 Harvard」：主記憶體共用（von Neumann），但 L1 cache 分為 L1-I（指令）和 L1-D（資料），兼具兩者優點。

In practice, modern CPUs are modified Harvard: main memory is shared (von Neumann), but L1 cache splits into L1-I (instruction) and L1-D (data) — best of both.

CPU 五大組件

二、CPU 五大組件

🧮 ALU (算術邏輯單元)

Arithmetic Logic Unit：執行加減乘除、比較、AND/OR/XOR 等運算。現代 CPU 含多個 ALU 與一個獨立 FPU（浮點單元）。

Arithmetic Logic Unit — performs add, sub, mul, div, compare, AND/OR/XOR. Modern CPUs have several ALUs and a separate FPU (float unit).

🎛️ Control Unit (控制單元)

解碼指令、發送控制訊號協調其他單元。可視為 CPU 的「交通指揮」。

Decodes instructions and emits control signals coordinating every other unit. Think of it as the CPU's traffic cop.

📥 Registers (暫存器)

CPU 內部最快的儲存單元，僅幾十到幾百個，但存取只需 1 個時脈週期。x86-64 有 16 個通用暫存器；ARM64 有 31 個。

The fastest storage inside a CPU — dozens to hundreds of slots, accessed in 1 cycle. x86-64 has 16 general-purpose registers; ARM64 has 31.

📌 Program Counter (PC)

儲存「下一條要執行的指令位址」。每執行一條指令就自動加 4（32-bit）或 8（64-bit），跳轉指令會直接改寫它。

Holds the address of the next instruction. Auto-increments by 4 (32-bit) or 8 (64-bit) per cycle; jumps rewrite it directly.

📋 Instruction Register (IR)

暫存當前正在執行的指令，供 Control Unit 解碼。

Holds the instruction currently being decoded by the Control Unit.

💨 Cache

L1 / L2 / L3 多級快取，緩衝 CPU 與主記憶體之間的速度差距（Ch 5 詳述）。

Multi-level L1/L2/L3 caches that bridge the CPU-DRAM speed gap (see Ch 5).

Fetch-Decode-Execute

三、機器週期

① Fetch

Control Unit 根據 PC 的位址，從記憶體（或 L1-I cache）讀出指令，存入 IR。PC 自動加 4。

Control unit uses PC to read an instruction from memory (or L1-I cache) into IR. PC auto-increments by 4.

② Decode

把 IR 中的 0/1 譯成「動作」：是加法？要讀哪個暫存器？要寫回哪？產生控制訊號。

Translate IR bits into actions: which op? which registers? where to write? Produce control signals.

③ Execute

ALU 完成運算；分支指令會比較條件並設旗標。

ALU performs the operation; branch instructions compare and set flags.

④ Memory

load/store 指令會在此階段讀寫主記憶體；非記憶體指令直接跳過。

Load/store instructions read or write main memory; others skip this stage.

⑤ Writeback

運算結果寫回目的暫存器。週期結束，回到 Fetch。

Write the result back to the destination register. End of cycle — return to Fetch.

管線化與危險

四、管線化 (Pipelining)

若一條指令花 5 個週期，CPU 每 5 cycle 才完成一條，太慢。管線化把五個階段重疊：第 1 條指令在 Execute 時，第 2 條在 Decode、第 3 條在 Fetch——理想上 每 cycle 完成 1 條指令（IPC=1），效能提升 5 倍。

但管線會遇到三種「危險 (hazard)」：

  • 資料危險 (Data hazard)：後一條指令需要前一條尚未寫回的結果 → 用轉送 (forwarding)或插入氣泡 (bubble)。
  • 控制危險 (Control hazard)：遇到分支，不確定下一條該取哪個位址 → 用分支預測 (branch prediction)，2026 年高階 CPU 預測準確率 > 98%。
  • 結構危險 (Structural hazard)：兩條指令同時需要同一硬體資源 → 增加單元或排程。

If one instruction takes 5 cycles, completing one every 5 cycles is too slow. Pipelining overlaps stages: while instruction 1 is in Execute, 2 is in Decode, 3 in Fetch — ideally 1 instruction per cycle (IPC=1), a 5× speedup.

Three classic hazards:

  • Data hazard: a later instruction needs a result not yet written back → use forwarding or insert a bubble.
  • Control hazard: branches make next-fetch ambiguous → use branch prediction (2026 high-end CPUs > 98% accurate).
  • Structural hazard: two instructions need the same hardware → add units or schedule around it.
⚠️
Spectre / Meltdown (2018)：分支預測的「投機執行」造成了史上最嚴重的 CPU 漏洞，幾乎所有 1995 年後的 CPU 都受影響。修補方案使部分指令慢了 5%–30%。
Spectre / Meltdown (2018): Speculative execution behind branch prediction caused the worst CPU vulnerabilities ever — nearly every CPU since 1995 was affected. Mitigations slowed some workloads by 5–30%.

2026 趨勢：① chiplet（多顆小晶粒封裝在一起，良率高、可混搭製程）；② 3D 堆疊（TSMC SoIC、Intel Foveros、AMD 3D V-Cache）；③ NPU 已內建於消費級 CPU；④ RISC-V 開源指令集快速崛起（嵌入式、AI 加速器、印度政府力推）。
2026 trends: (1) chiplets — multiple smaller dies in one package (better yield, mixed process); (2) 3D stacking (TSMC SoIC, Intel Foveros, AMD 3D V-Cache); (3) NPUs now standard in consumer CPUs; (4) RISC-V open ISA surging in embedded, AI accelerators, and government-backed Indian/EU chips.

八、動手試

# 量測 CPU 單核加法吞吐量 / Measure single-core add throughput
import time

N = 10_000_000
start = time.perf_counter()
total = 0
for i in range(N):
    total += i
elapsed = time.perf_counter() - start

print(f"{N:,} adds in {elapsed:.3f}s")
print(f"≈ {N/elapsed/1e6:.1f} M adds/sec")
# 純 Python ~50M/s；NumPy 向量化可達 ~5000M/s（用 SIMD）
# Pure Python ~50M/s; NumPy vectorized ~5000M/s (uses SIMD)

import numpy as np
a = np.arange(N, dtype='int64')
start = time.perf_counter()
total = a.sum()
elapsed = time.perf_counter() - start
print(f"NumPy sum: {N/elapsed/1e9:.2f} G ops/sec")

# 已排序陣列 → 分支可預測 → 快；隨機陣列 → 預測失敗 → 慢 2–3 倍
# Sorted array → predictable branches; random → 2-3× slowdown
// Fetch-Decode-Execute 主迴圈 / Machine cycle main loop
while CPU is running:
    instr = MEMORY[PC]              // ① Fetch
    PC = PC + 4
    (op, rs, rt, rd) = Decode(instr) // ② Decode
    switch op:                      // ③ Execute
        case ADD:  REG[rd] = REG[rs] + REG[rt]
        case SUB:  REG[rd] = REG[rs] − REG[rt]
        case LOAD: REG[rd] = MEMORY[REG[rs]]   // ④ Memory
        case STORE: MEMORY[REG[rs]] = REG[rt]
        case BEQ:  if REG[rs] == REG[rt]: PC = target
    // ⑤ Writeback already happened above
