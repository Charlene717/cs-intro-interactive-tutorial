CPU 與計算機組織

你手中的 iPhone 比 1969 阿波羅 11 號的登月電腦快 1 億倍，但寫程式的核心原則沒變——Fetch、Decode、Execute。本章帶你拆解一顆 2026 旗艦 CPU 的每一個齒輪。

Your iPhone is 100 million times faster than the Apollo 11 lunar computer, yet the programming principles haven't changed — Fetch, Decode, Execute. This chapter takes apart every gear in a 2026 flagship CPU.

1 億倍的世代差距

一、口袋裡比登月電腦強一億倍

1969 年 7 月 20 日，阿波羅 11 號登月導引電腦 (AGC)用 64 KB ROM、4 KB RAM、2.048 MHz 時脈把人類送上月球。它的計算能力大約是每秒 40,000 次加法，重 32 公斤，耗電 70 W。

2024 年的 iPhone 16 Pro (A18 Pro)：每秒約 5 兆次運算（5 × 10¹²），重 199 克，使用 ~3 W。比 AGC 快 1.25 億倍、輕 160 倍、省電 23 倍。每隔 6 年，「口袋裡的運算力」就再翻百倍。

但寫程式的核心原則一點都沒變：Fetch（取指）→ Decode（解碼）→ Execute（執行）→ Writeback（寫回）。從 Babbage 的齒輪、ENIAC 的真空管、Intel 4004 的 2,300 顆電晶體、到今天的 208 億顆 ARM 核心——每顆 CPU 都在重複這個迴圈。

20 July 1969. The Apollo 11 Guidance Computer (AGC), with 64 KB ROM, 4 KB RAM, and a 2.048 MHz clock, put humans on the Moon. Its compute? Around 40,000 adds/sec. Weight: 32 kg. Power: 70 W.

2024's iPhone 16 Pro (A18 Pro): about 5 trillion ops/sec (5 × 10¹²). Weight 199 g, power ~3 W. 125 million × faster, 160× lighter, 23× less power. Every six years, pocket compute multiplies by ~100×.

And yet the programming basics are unchanged: Fetch → Decode → Execute → Writeback. From Babbage's gears, ENIAC's tubes, Intel 4004's 2,300 transistors, to today's 20.8-billion-transistor ARM cores — every CPU repeats this loop.

💡
核心觀念：CPU 並不「理解」程式。它只是不斷讀取記憶體裡的 0/1，按照硬體電路的規則動作。所謂「智慧」來自程式設計師寫的指令序列。 Core idea: A CPU does not "understand" programs — it just reads 0/1 from memory and reacts per hardware rules. The "intelligence" comes from the programmer's instruction sequence.
von Neumann vs Harvard

二、von Neumann vs Harvard 架構

特性von NeumannHarvard
指令與資料記憶體Instruction & data memory共用同一記憶體分開存放
匯流排Buses單條（瓶頸）分離（指令+資料可同時讀）
代表應用Typical usePC、伺服器、智慧手機微控制器、DSP、AI 加速器
優點Pros設計簡單、彈性高（程式即資料）效能高、可同時取指與資料
缺點Cons"von Neumann 瓶頸"硬體成本高

實務上，現代 CPU 是「修改型 Harvard (modified Harvard)」：主記憶體共用（von Neumann），但 L1 cache 分為 L1-I（指令快取） 和 L1-D（資料快取），可同時讀寫——兼具兩者優點。Apple M4 的 L1 cache 是 192 KB 指令 + 128 KB 資料；Intel Core Ultra 是 64 KB + 48 KB。

In practice, modern CPUs are modified Harvard: main memory is shared (von Neumann), but L1 cache splits into L1-I (instruction) and L1-D (data) — best of both. Apple M4 has 192 KB L1-I + 128 KB L1-D; Intel Core Ultra has 64 KB + 48 KB.

CPU 五大組件

三、CPU 五大組件

🧮 ALU

Arithmetic Logic Unit：執行加減乘除、比較、AND/OR/XOR。現代 CPU 內含多個 ALU + 獨立 FPU（浮點單元）+ SIMD 單元（AVX-512/NEON）。

Performs add, sub, mul, div, compare, AND/OR/XOR. Modern CPUs have several ALUs + separate FPU + SIMD units (AVX-512/NEON).

🎛️ Control Unit

解碼指令、發送控制訊號協調其他單元。可視為 CPU 的「交通指揮」。

Decodes instructions, sends control signals coordinating every other unit. Think of it as the CPU's traffic cop.

📥 Registers

CPU 內部最快的儲存單元，僅幾十個，但存取只需 1 個時脈週期。x86-64 有 16 個通用暫存器；ARM64 有 31 個；RISC-V 有 32 個。

The fastest storage inside a CPU — dozens of slots, accessed in 1 cycle. x86-64 has 16 general-purpose; ARM64 has 31; RISC-V has 32.

📌 Program Counter

儲存「下一條要執行的指令位址」。每執行一條指令就自動加 4（32-bit）或 8（64-bit），跳轉指令會直接改寫它。

Holds the address of the next instruction. Auto-increments by 4 (32-bit) or 8 (64-bit); jumps rewrite it directly.

📋 Instruction Register

暫存當前正在執行的指令，供 Control Unit 解碼。

Holds the instruction currently being decoded by the Control Unit.

💨 Cache

L1 / L2 / L3 多級快取，緩衝 CPU 與主記憶體之間的速度差距（Ch 5 詳述）。沒有 cache，CPU 跑得再快也只能等記憶體。

Multi-level L1/L2/L3 caches bridge the CPU-DRAM speed gap (see Ch 5). Without cache, even the fastest CPU stalls on memory.

Fetch-Decode-Execute

四、機器週期

① Fetch

Control Unit 根據 PC 的位址，從記憶體（或 L1-I cache）讀出指令，存入 IR。PC 自動加 4。

Control unit uses PC to read an instruction from memory (or L1-I cache) into IR. PC auto-increments by 4.

② Decode

把 IR 中的 0/1 譯成「動作」：是加法？要讀哪個暫存器？要寫回哪？產生控制訊號。x86 的 micro-ops 拆解也在此步。

Translate IR bits into actions: which op? which registers? where to write? Produce control signals. x86 micro-op cracking happens here.

③ Execute

ALU 完成運算；分支指令會比較條件並設旗標。可能多個 ALU 並行（super-scalar）。

ALU performs the operation; branch instructions compare and set flags. Multiple ALUs may execute in parallel (superscalar).

④ Memory

load/store 指令會在此階段讀寫主記憶體；非記憶體指令直接跳過。L1 cache 命中 ~4 cycle、L2 ~12、L3 ~40、DRAM ~200。

Load/store instructions read or write main memory; others skip this stage. Hits: L1 ~4 cycles, L2 ~12, L3 ~40, DRAM ~200.

⑤ Writeback

運算結果寫回目的暫存器。週期結束，回到 Fetch。

Write the result back to the destination register. End of cycle — return to Fetch.

管線化 + 危險

五、管線化與三種危險

若一條指令花 5 個週期，CPU 每 5 cycle 才完成一條，太慢。管線化 (pipelining) 把五個階段重疊：第 1 條指令在 Execute 時，第 2 條在 Decode、第 3 條在 Fetch——理想上 每 cycle 完成 1 條指令（IPC=1），效能提升 5 倍。

現代高階 CPU 用深管線 + 超純量：Intel P-core 約 14 級管線、Apple M4 約 12 級；同時擁有 6–8 條執行通道（IPC 可達 6–8）。但管線會遇到三種「危險 (hazard)」：

  • ① 資料危險 (Data hazard)：後一條指令需要前一條尚未寫回的結果。例：R1 = R2 + R3 後緊接 R4 = R1 × R5。解法：轉送 (forwarding) 直接把 EX 階段的結果遞給下一個 EX，省去等寫回；或插入氣泡 (bubble)。
  • ② 控制危險 (Control hazard)：遇到分支 (if/while)，不確定下一條該取哪個位址。解法：分支預測 (branch prediction)，2026 高階 CPU 用 TAGE 演算法準確率 > 98%。但這就是 Spectre 漏洞的源頭。
  • ③ 結構危險 (Structural hazard)：兩條指令同時需要同一硬體資源（如同一個 ALU）。解法：增加單元（超純量）或重排執行順序 (out-of-order execution)。

If one instruction takes 5 cycles, completing one every 5 cycles is too slow. Pipelining overlaps stages: while instruction 1 is in Execute, 2 is in Decode, 3 in Fetch — ideally 1 instruction per cycle (IPC=1), a 5× speedup.

Modern high-end CPUs use deep pipelines + superscalar: Intel P-core ~14 stages, Apple M4 ~12; 6–8 execution lanes (IPC reaches 6–8). But pipelines face three hazards:

  • ① Data hazard: a later instruction needs a result not yet written back. E.g., R1 = R2 + R3 followed by R4 = R1 × R5. Fix: forwarding (pass EX result directly to next EX) or insert a bubble.
  • ② Control hazard: branches make next-fetch ambiguous. Fix: branch prediction — 2026 high-end CPUs use TAGE with >98% accuracy. This is the root of the Spectre vulnerability.
  • ③ Structural hazard: two instructions need the same hardware (e.g., one ALU). Fix: add units (superscalar) or reorder execution (out-of-order).
🚨
Spectre / Meltdown (2018)：分支預測的「投機執行」造成史上最嚴重的 CPU 漏洞——攻擊者誘導 CPU「猜錯」並執行受限的記憶體存取，雖然事後撤銷，但 cache side-channel 殘留洩漏內容。幾乎所有 1995 年後的 CPU 都受影響，連 ARM、Apple M 系列都不能倖免。修補方案讓部分指令慢 5–30%。後續還有 Foreshadow、ZombieLoad、Retbleed 等變種。
Spectre / Meltdown (2018): Speculative execution behind branch prediction caused the worst CPU vulnerabilities ever — attackers trick the CPU into "guessing wrong" and accessing restricted memory; though rolled back, cache side-channels leak the content. Nearly every CPU since 1995 was affected, even ARM and Apple M. Mitigations cost 5–30%. Variants since: Foreshadow, ZombieLoad, Retbleed.

四個經典故事

七、四個經典故事

🇮🇹 Intel 4004：Faggin 的故事

1971 年義大利移民 Federico Faggin 在 Intel 設計史上第一顆商用微處理器 4004：2,300 顆電晶體、4-bit、108 KHz、10 μm 製程。原本只是給日本 Busicom 計算機代工，Intel 副總 Hoff 卻看見潛力。Faggin 在每顆晶片角落刻上自己的縮寫 "F.F."——這是 CPU 史上第一個「設計師簽名」。50 年後，Faggin 接受訪問說：「我們當時根本不知道在發明什麼。」

In 1971, Italian immigrant Federico Faggin at Intel designed the first commercial microprocessor: 2,300 transistors, 4-bit, 108 KHz, 10 μm. It was originally a contract chip for Japan's Busicom calculator, but Intel VP Hoff saw the potential. Faggin etched "F.F." in every chip's corner — the first "designer's signature" in CPU history. 50 years later he reflected: "We had no idea what we were inventing."

🍎 Apple M1 (2020)

2020 年 11 月 Apple 推出 M1——首顆採用 5nm + Big.LITTLE + 統一記憶體 (UMA) 的個人電腦 CPU。CPU 和 GPU 共用同一塊 DRAM，省去 PCIe 拷貝。同尺寸下效能比 Intel 高 50%、功耗降 70%。隔年第一次「ARM Mac」銷量超越 Intel Mac。對 scRNA-seq 等大資料分析特別重要——scvi-tools 在 M1 Max 64GB 上跑 5 萬細胞，比同價位 Intel 機快 3 倍。

In Nov 2020, Apple released the M1 — the first PC CPU with 5nm + Big.LITTLE + unified memory (UMA). CPU and GPU share the same DRAM, skipping PCIe copies. 50% more performance and 70% less power vs Intel of the same size. ARM Macs outsold Intel Macs in their first year. Huge for big-data work: scvi-tools on a 64 GB M1 Max processes 50,000 cells 3× faster than an Intel machine at the same price.

⚔️ RISC vs CISC：40 年聖戰

1980s Berkeley 的 David Patterson 與 Stanford 的 John Hennessy 提出 RISC（指令少而簡單），預測會擊敗 CISC（指令多而複雜，如 x86）。1990s x86 用「micro-op 解碼」把 CISC 轉成內部 RISC 才追上。2010s ARM 進入手機、伺服器；2024 Apple 全部改 ARM、AWS Graviton4、印度政府力推 RISC-V——RISC 終於贏了。Patterson 與 Hennessy 2017 共得圖靈獎。

In the 1980s, Berkeley's David Patterson and Stanford's John Hennessy proposed RISC (few, simple instructions) over CISC (many, complex — like x86). In the 1990s, x86 caught up by internally decoding to RISC-like micro-ops. 2010s: ARM dominates phones and servers; 2024: Apple is all-ARM, AWS Graviton4, India pushes RISC-V — RISC finally won. Patterson and Hennessy shared the 2017 Turing Award.

🐛 Pentium FDIV bug (1994)

1994 年數學教授 Thomas Nicely 發現 Intel Pentium 的浮點除法在某些罕見值出錯（4195835.0 / 3145727.0 結果差 1.5 ppm）。Intel 一開始拒換，被媒體痛批後改弦更張，全面召回，花費 $4.75 億美元。從此「Intel 品質」神話破滅，也啟發了之後嚴謹的 CPU 形式驗證——Hennessy 後來說：「FDIV bug 讓 Intel 學到，CPU 與其他軟體不一樣，沒有 patch 補丁這回事。」

In 1994, math professor Thomas Nicely found Intel's Pentium FPU divided incorrectly on rare values (4195835.0 / 3145727.0 off by 1.5 ppm). Intel initially refused replacements; after media outcry, it issued a full recall costing $475 million. Intel's quality myth broke, and the industry invested in formal CPU verification. Hennessy: "FDIV taught Intel that CPUs aren't software — there's no patch."

給生資人

九、🧬 給生物資訊學家

🧬
給生物資訊學家：選對 CPU 決定生資速度

BWA-MEM2 為何加速 4×？因為它用 SIMD AVX-512。AlphaFold 為何需要 GPU？因為矩陣運算高度可平行。理解 CPU 架構，能讓你選對硬體、設定對 thread 數、避開「核心多但 Amdahl 卡住」的陷阱。

Why is BWA-MEM2 4× faster? AVX-512 SIMD. Why does AlphaFold need GPUs? Highly parallel matrix math. Understanding CPU architecture lets you pick the right hardware, set the right thread count, and avoid the "many-core but Amdahl-limited" trap.

🧬 BWA / STAR：多核心

BWA、STAR、minimap2 的 seed-and-extend 演算法天然可平行——每條 read 獨立比對，無資料相依。在 24 核 EPYC 上 -t 24 接近線性加速。但寫入 BAM 時是序列瓶頸，需 samtools sort -@ N 配合。實務建議：對齊 thread = 物理核心數（不要 hyperthread），fastp 也是；samtools sort thread = 4–8 就好（受 I/O 限制）。

BWA, STAR, minimap2's seed-and-extend is embarrassingly parallel — each read aligns independently. On a 24-core EPYC, -t 24 scales nearly linearly. But BAM writing is serial; pair with samtools sort -@ N. Practical tip: alignment threads = physical cores (not hyperthreads); fastp too. samtools sort threads = 4–8 (I/O-bound).

⚡ SIMD：MAFFT、HMMER3

SIMD (Single Instruction Multiple Data) 讓一條指令同時處理 4–16 個資料元素。HMMER3 (Eddy 2011 PLOS Comp Biol) 用 SSE2/AVX2 把 profile HMM 比對加速 100×。MAFFT 用 SIMD 把多序列比對加速 16×。BWA-MEM2 (Vasimuddin 2019) 用 AVX-512 比 BWA-MEM 快 1.8–3.2×。確認你的 CPU 支援：cat /proc/cpuinfo | grep -E 'sse|avx'。

SIMD (Single Instruction Multiple Data) processes 4–16 data elements per instruction. HMMER3 (Eddy 2011 PLOS Comp Biol) uses SSE2/AVX2 for a 100× profile-HMM speedup. MAFFT uses SIMD for 16× faster multi-seq alignment. BWA-MEM2 (Vasimuddin 2019) uses AVX-512 for 1.8–3.2× over BWA-MEM. Check support: cat /proc/cpuinfo | grep -E 'sse|avx'.

🎮 GPU：AlphaFold、scGPT

Transformer 推論（AlphaFold2/3、ESM-2、scGPT）有 90%+ 計算量是大矩陣乘法——GPU 強項。NVIDIA A100 (FP32 19.5 TFLOPS) 比 16-core CPU (1 TFLOPS) 快 ~20×；H100 FP8 ~3 PFLOPS 又快 100×。實務：單細胞 atlas 訓練 → A100 80GB；FoldDock 推論 → 一張 RTX 4090 24GB 就夠；scGPT 微調 → 至少 40GB GPU。CPU 只用於資料載入與後處理。

Transformer inference (AlphaFold2/3, ESM-2, scGPT) is 90%+ large matrix multiplies — GPU territory. NVIDIA A100 (FP32 19.5 TFLOPS) is ~20× a 16-core CPU (1 TFLOPS); H100 FP8 ~3 PFLOPS is 100× more. Practical: single-cell atlas training → A100 80GB; FoldDock inference → one RTX 4090 24GB; scGPT fine-tuning → ≥40 GB GPU. CPUs only handle data loading and post-processing.

🍏 Apple M：UMA 救星

scRNA-seq 大資料分析 (Scanpy、scvi-tools、scGPT) 常被 RAM ↔ GPU 拷貝拖慢。Apple M-series 的統一記憶體 (UMA) 讓 CPU 和 GPU 共用同一塊 DRAM，零拷貝。M3 Max 128 GB 上跑 100 萬細胞 PBMC atlas，比同價位 Intel + RTX 4090 工作站快 1.5–3 倍——尤其是「載入大型 AnnData → 跑 PCA → 訓 scVI → UMAP」這整條 pipeline。缺點：CUDA 生態不在 M 上原生，需依賴 MLX (Apple) 或 PyTorch MPS backend。

Big-data scRNA-seq (Scanpy, scvi-tools, scGPT) is often bottlenecked by RAM↔GPU copies. Apple M's unified memory (UMA) means CPU and GPU share DRAM — zero-copy. An M3 Max 128 GB runs a 1M-cell PBMC atlas 1.5–3× faster than a same-priced Intel + RTX 4090 box — especially for "load AnnData → PCA → train scVI → UMAP." Drawback: CUDA isn't native on M; use MLX (Apple) or PyTorch MPS.

五個常見誤解

十三、常見誤解

🚨
誤解 #1：「時脈高 = CPU 快」——錯。速度 = Clock × IPC。Apple M3 (4.05 GHz, IPC ~8) 比 Intel Core Ultra (5.7 GHz, IPC ~5) 整體效能高，因為 IPC 大兩倍。AMD 90s 的「PR Rating」就是承認時脈不能單獨代表速度。
Myth #1: "Higher clock = faster CPU." Wrong. Speed = Clock × IPC. Apple M3 (4.05 GHz, IPC ~8) often outperforms Intel Core Ultra (5.7 GHz, IPC ~5). AMD's 1990s "PR Rating" acknowledged that clock alone is misleading.
🚨
誤解 #2：「核心多 = 必定快」——錯。Amdahl 定律說：speedup = 1 / ((1−P) + P/N)，P 是可平行比例。若 P=0.95，N=64 → speedup 僅 16.6 倍（不是 64）。序列部分主宰結果。實務：不要盲目給 BAM merging 64 thread——磁碟 I/O 才 4–8 thread 就飽和。
Myth #2: "More cores = always faster." Wrong. Amdahl's Law: speedup = 1 / ((1−P) + P/N), P = parallel fraction. With P=0.95, N=64 → only 16.6× (not 64). The serial part dominates. Practical: don't blindly give BAM merge 64 threads — disk I/O saturates at 4–8.
⚠️
誤解 #3：「Hyperthread = 真實核心」——錯。Intel Hyperthreading (Apple/AMD 也有 SMT) 讓一個物理核心同時跑 2 個邏輯執行緒，共享 ALU 與 cache。對 BWA、AlphaFold 這類 CPU-bound 工具，hyperthread 只加 20–40% 效能，不是 2 倍。對 I/O-bound 工作（資料庫、網頁伺服器）才接近 2 倍。
Myth #3: "Hyperthread = real core." Wrong. Intel Hyperthreading (Apple/AMD also have SMT) lets one physical core run two logical threads, sharing ALUs and cache. For CPU-bound tools (BWA, AlphaFold), hyperthreading adds only 20–40%, not 2×. I/O-bound work (DBs, web servers) approaches 2×.
⚠️
誤解 #4：「GPU 永遠比 CPU 快」——錯。GPU 在並行矩陣運算勝出（AlphaFold、scGPT）；但 GPU 啟動 kernel 有 5–20 μs 延遲，對小資料、分支密集工作（BWA seeding、BAM index 查詢）反而慢過 CPU。實務：「先 CPU 再 GPU」常是正解（CPU 做 I/O + 預處理，GPU 做矩陣乘）。
Myth #4: "GPU is always faster than CPU." Wrong. GPUs excel at parallel matrix ops (AlphaFold, scGPT); but GPU kernel launch has 5–20 μs latency, making them slower than CPUs on small, branchy workloads (BWA seeding, BAM index queries). Rule: CPU first (I/O + preprocessing), then GPU (matmul).
⚠️
誤解 #5：「Spectre / Meltdown 已修補了，可以忽略」——錯。新變種還在不斷出現：Foreshadow (2018)、ZombieLoad (2019)、CrossTalk (2020)、Retbleed (2022)、Inception (2023)、GoFetch (2024)、SLAM (2024)。雲端共享環境（AWS EC2、GCP）要特別小心 cross-tenant 側通道；單機通常不用擔心。
Myth #5: "Spectre/Meltdown is patched; ignore it." Wrong. New variants keep appearing: Foreshadow (2018), ZombieLoad (2019), CrossTalk (2020), Retbleed (2022), Inception (2023), GoFetch (2024), SLAM (2024). Shared-cloud (AWS EC2, GCP) needs cross-tenant side-channel scrutiny; single-tenant usually fine.

十四、延伸思考

  1. Spectre 教我們什麼？ 投機執行帶來 ~30% 效能，但安全代價是？「為了安全，是否該禁用 speculative execution？」業界至今仍在拉鋸。
  2. What does Spectre teach us? Speculative execution gives ~30% performance, but at what security cost? "Should we disable speculation for security?" The industry still debates.
  3. 神經型態 CPU 會取代 von Neumann 嗎？ Intel Loihi 2、IBM NorthPole 用「事件驅動」突破 von Neumann 瓶頸——但通用性差。它能取代主流 CPU 嗎？還是只當 AI 加速器？
  4. Will neuromorphic chips replace von Neumann? Intel Loihi 2, IBM NorthPole are "event-driven," beating the von Neumann bottleneck — but lack generality. Mainstream replacement? Or AI-only accelerator?
  5. RISC-V 開源 ISA 的長遠影響？ 印度政府、歐盟、Tenstorrent、Meta 都已採用。它能像 Linux 一樣統一硬體生態嗎？對生資意味著什麼？
  6. Long-term impact of RISC-V open ISA? India, EU, Tenstorrent, Meta have adopted it. Will it unify hardware like Linux unified OSes? What does it mean for bioinformatics?
  7. Apple 統一記憶體：未來主流？ 若所有 CPU 都採 UMA + chiplet，那「離散 GPU + PCIe」設計還有存在價值嗎？對大 atlas scRNA-seq 工作流意義為何？
  8. Apple's unified memory: the future mainstream? If all CPUs adopt UMA + chiplet, do discrete GPUs + PCIe still make sense? What does it mean for large atlas scRNA-seq workflows?
  9. FPGA 在生資能贏 GPU 嗎？ Illumina DRAGEN 用 FPGA 跑 BWA + GATK 比純 CPU 快 30×。為何 GPU 沒大規模取代它？
