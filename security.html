資訊安全與密碼學

從 CIA 三要素、AES/RSA、TLS 1.3 到 2026 年 NIST 後量子標準與 Zero Trust——學會在量子威脅時代保護資料。

From the CIA triad, AES/RSA, TLS 1.3 to 2026's NIST post-quantum standards and Zero Trust — protect data in the quantum era.

概覽

為什麼資安比以往任何時候都重要？

2025 全球資料外洩平均成本已達 488 萬美元（IBM Cost of a Breach 報告），勒索軟體攻擊每 11 秒發生一次。資安不是「IT 部門的問題」——它是任何接觸資料的人都必須懂的工程素養。

資安的核心目標稱為 CIA 三要素：

  • Confidentiality（機密性）：只有授權對象能讀取——靠加密。
  • Integrity（完整性）：資料未被竄改——靠 hash 與簽章。
  • Availability（可用性）：服務在需要時可用——靠備援與抗 DDoS。

In 2025 the average cost of a data breach hit USD 4.88 million (IBM Cost of a Breach report), and a ransomware attack occurs every 11 seconds. Security isn't "the IT team's job" — it's engineering literacy for anyone who touches data.

The core goals are the CIA triad:

  • Confidentiality: only authorized parties can read — via encryption.
  • Integrity: data has not been tampered with — via hashes and signatures.
  • Availability: service is reachable when needed — via redundancy and DDoS mitigation.
💡
STRIDE 威脅模型：微軟提出，涵蓋 Spoofing（偽冒）、Tampering（竄改）、Repudiation（否認）、Information disclosure（洩漏）、Denial of service（阻斷）、Elevation of privilege（提權）——設計系統時逐項自問是最常見的威脅建模手法。 STRIDE threat model: Microsoft's checklist — Spoofing, Tampering, Repudiation, Information disclosure, Denial of service, Elevation of privilege. Walking through each category during design is the most common threat-modeling technique.
加密兩大家族

一、對稱 vs 非對稱加密

類別代表演算法金鑰速度典型用途
對稱（Symmetric）SymmetricAES-256、ChaCha20、3DES同一把金鑰加密/解密Same key encrypts/decrypts快（GB/s 等級）Fast (GB/s)大量資料加密、磁碟加密Bulk data, disk encryption
非對稱（Asymmetric）AsymmetricRSA-2048/4096、ECC (P-256, Ed25519)、Diffie-Hellman公鑰加密、私鑰解密Public key encrypts, private key decrypts慢（MB/s 等級）Slow (MB/s)金鑰交換、數位簽章Key exchange, digital signatures

AES (Advanced Encryption Standard)：2001 年 NIST 標準化，使用 128/192/256-bit 金鑰、區塊大小固定 128-bit。AES-256 至今未被破解，是大多數 VPN、磁碟加密、HTTPS 的底層。

ChaCha20：串流密碼 (stream cipher)，由 Daniel Bernstein 設計，在沒有 AES 硬體加速的行動裝置上比 AES 快。Google QUIC / TLS 1.3 將其列為標準。

RSA vs ECC：RSA-2048 相當於 ECC-224 的安全強度，但 ECC 金鑰短得多（速度也更快）。Ed25519 是 SSH、Tor、Signal 主流。

Diffie-Hellman 金鑰交換：兩方在公開頻道交換訊息後得出同一把對稱金鑰，竊聽者卻算不出——TLS 1.3 強制使用 ECDHE（橢圓曲線版）。

AES: standardized by NIST in 2001, with 128/192/256-bit keys and fixed 128-bit blocks. AES-256 remains unbroken and underpins most VPNs, disk encryption, and HTTPS.

ChaCha20: a stream cipher by Daniel Bernstein. On mobile CPUs without AES-NI it outpaces AES; Google's QUIC and TLS 1.3 adopt it as a standard.

RSA vs ECC: RSA-2048 has roughly the same strength as ECC-224, but ECC keys are far smaller and faster. Ed25519 dominates SSH, Tor, and Signal.

Diffie-Hellman key exchange: two parties exchange public values and derive the same secret key; an eavesdropper cannot. TLS 1.3 mandates ECDHE (elliptic-curve variant).

Hash 與數位簽章

二、Hash 函式、簽章與 PKI

密碼學雜湊函式 (Cryptographic hash) 將任意長度資料壓縮為固定長度的「指紋」。三大特性：

  • 單向性 (one-way)：從 hash 反推原文在計算上不可行。
  • 抗碰撞 (collision-resistant)：不易找出兩個不同輸入產生相同 hash。
  • 雪崩效應 (avalanche)：輸入改 1 個 bit，輸出約有一半 bit 翻轉。

A cryptographic hash function compresses arbitrary input into a fixed-size "fingerprint". Three properties:

  • One-way: infeasible to invert.
  • Collision-resistant: hard to find two inputs with the same hash.
  • Avalanche: flipping one input bit flips ~half the output bits.

數位簽章流程：① 對訊息算 hash；② 用私鑰加密 hash → 簽章；③ 驗證者用公鑰解密簽章，與自己算的 hash 比對。能保證來源 + 完整性 + 不可否認。

PKI / X.509 / Let's Encrypt：公鑰必須有人「認證」屬於誰。憑證授權機構 (CA) 簽發 X.509 憑證，瀏覽器內建根 CA 清單。Let's Encrypt（2016 起免費自動化）已簽發超過 50 億張憑證，是 HTTPS 普及的最大功臣。

Digital signature flow: (1) hash the message; (2) encrypt the hash with your private key → signature; (3) verifier decrypts with your public key and compares. Provides authenticity + integrity + non-repudiation.

PKI / X.509 / Let's Encrypt: public keys need attestation. Certificate Authorities (CAs) issue X.509 certs; browsers ship a root-CA list. Let's Encrypt (free + automated since 2016) has issued 5 billion+ certs and is the main reason HTTPS is now ubiquitous.

TLS 1.3 與 HTTPS

三、TLS 1.3 握手

ClientHello

瀏覽器送出支援的密碼套件、隨機數、ECDHE 公鑰份額。

Browser sends supported cipher suites, random, and ECDHE key share.

ServerHello + Cert

伺服器選一組密碼套件、附上 X.509 憑證鏈、自己的 ECDHE 公鑰份額。雙方各自算出共享密鑰。

Server picks cipher suite, sends X.509 chain and its own ECDHE share. Both sides derive the shared secret.

Finished

雙方用衍生金鑰加密一條「Finished」訊息驗證對方真的解出來了。TLS 1.3 僅需 1-RTT（甚至 0-RTT）就完成。

Both sides exchange encrypted "Finished" messages to prove they derived the same key. TLS 1.3 needs just 1-RTT (or 0-RTT resumption).

Application data

之後所有 HTTP 內容皆以對稱加密 (AES-GCM 或 ChaCha20-Poly1305) 保護。

All subsequent HTTP traffic is protected with symmetric AEAD (AES-GCM or ChaCha20-Poly1305).

OWASP Top 10 2025

四、OWASP Top 10 2025 排名變化

OWASP Top 10 是「Web 應用最危險的 10 類弱點」清單。2025 版改動重點：A01 Broken Access Control 仍居首；A02 升為 Security Misconfiguration（原為加密失敗）；A06 改為 Software Supply Chain Failures（涵蓋 SolarWinds 級事件）；A10 新增 Mishandling of Exceptional Conditions。

OWASP Top 10 lists the most dangerous web-app risks. Key 2025 changes: A01 Broken Access Control still #1; A02 elevated to Security Misconfiguration (replacing crypto failures); A06 renamed Software Supply Chain Failures (covers SolarWinds-class events); A10 new Mishandling of Exceptional Conditions.

Attack cheat sheet: SQL Injection (prepared statements), XSS (CSP + escaping), CSRF (SameSite cookies), Phishing (MFA + security keys), Ransomware (offline backups), Supply Chain (SBOM + lockfiles).
後量子密碼學

五、後量子密碼學

足夠大的量子電腦可用 Shor 演算法於數小時內破解 RSA-2048 與 ECC。NIST 自 2016 啟動 PQC 競賽，2024 年公布前三套標準，2026 起政府與大型雲端業者陸續部署：

A large enough quantum computer could use Shor's algorithm to break RSA-2048 and ECC in hours. NIST started its PQC competition in 2016 and finalized the first three standards in 2024; government and hyperscaler deployment begins 2026:

⚠️
「現在收割、未來解密」(Harvest Now, Decrypt Later)：攻擊者今天就可以擷取加密流量保存，等未來量子電腦成熟再解密——所以高機敏資料應「現在」就改用 PQC 或混合模式 (X25519+ML-KEM)。
Harvest Now, Decrypt Later: attackers can capture encrypted traffic today and decrypt it once quantum is mature. High-sensitivity data should migrate to PQC or hybrid (X25519+ML-KEM) now.

Zero Trust 架構：傳統「內網可信、外網不可信」已過時。Zero Trust 原則：never trust, always verify——每個請求都要驗證身分、裝置、上下文。Google BeyondCorp、Cloudflare Access 是代表實作。

Zero Trust architecture: the old "trust the LAN, distrust the WAN" model is dead. Zero Trust principle: never trust, always verify — every request authenticates identity, device, and context. Google BeyondCorp and Cloudflare Access are reference implementations.

六、決策樹：選擇密碼學方案

🌳 我該用什麼密碼學方案？

Q1:
只想驗證資料完整性（不加密）？→ 用 SHA-256 或 HMAC-SHA256。
Q2:
儲存使用者密碼？→ 用 Argon2id（次選 bcrypt），絕不用 MD5/SHA1。
Q3:
加密大量資料（檔案/磁碟/串流）？→ 用對稱 AES-256-GCM 或 ChaCha20-Poly1305。
Q4:
兩端共享金鑰？→ 用 ECDHE (X25519)；高機敏資料改為 X25519 + ML-KEM 混合。
Q5:
簽章與身分驗證？→ Ed25519（現在）或 ML-DSA（後量子）。
Q1:
Just verify integrity (no encryption)? → Use SHA-256 or HMAC-SHA256.
Q2:
Storing user passwords? → Use Argon2id (or bcrypt); never MD5/SHA1.
Q3:
Encrypting bulk data (files/disks/streams)? → Symmetric AES-256-GCM or ChaCha20-Poly1305.
Q4:
Establish a shared key? → ECDHE (X25519); for sensitive data add ML-KEM hybrid.
Q5:
Signatures & authentication? → Ed25519 (today) or ML-DSA (post-quantum).
程式碼

七、動手做

# pip install cryptography
from cryptography.hazmat.primitives.ciphers.aead import AESGCM
from cryptography.hazmat.primitives.asymmetric import rsa, padding
from cryptography.hazmat.primitives import hashes
import os, hashlib

# 1) AES-256-GCM 對稱加密 / Symmetric encryption
key   = AESGCM.generate_key(bit_length=256)
nonce = os.urandom(12)                          # GCM 推薦 96-bit nonce
aes   = AESGCM(key)
ct    = aes.encrypt(nonce, b"Top secret", None)
pt    = aes.decrypt(nonce, ct, None)        # b'Top secret'

# 2) RSA 簽章 / RSA signature
priv = rsa.generate_private_key(public_exponent=65537, key_size=2048)
msg  = b"transfer $100 to Alice"
sig  = priv.sign(msg, padding.PSS(mgf=padding.MGF1(hashes.SHA256()),
                                  salt_length=padding.PSS.MAX_LENGTH),
                 hashes.SHA256())
priv.public_key().verify(sig, msg, padding.PSS(mgf=padding.MGF1(hashes.SHA256()),
                                          salt_length=padding.PSS.MAX_LENGTH),
                            hashes.SHA256())          # 不丟例外 = 驗證通過

# 3) SHA-256 雪崩效應演示 / Avalanche effect
print(hashlib.sha256(b"hello").hexdigest())
print(hashlib.sha256(b"Hello").hexdigest())   # 兩個 hash 完全不同！
// SHA-256 高階流程 / High-level SHA-256 flow
function SHA256(message):
    message = Pad(message)                   // 填補到 512-bit 倍數
    H = [h0, h1, ..., h7]                  // 8 個 32-bit 初始值
    for each 512-bit block in message:
        W = ExpandToWords(block, 64)        // 展開為 64 個字
        (a..h) = H
        for t = 0 to 63:
            T1 = h + Σ1(e) + Ch(e,f,g) + K[t] + W[t]
            T2 = Σ0(a) + Maj(a,b,c)
            h = g; g = f; f = e; e = d + T1
            d = c; c = b; b = a; a = T1 + T2
        H = H + (a..h)                     // 累加，模 2^32
    return concat(H)                       // 256-bit digest
