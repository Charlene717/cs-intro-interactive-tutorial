雲端、邊緣與 IoT

從 IaaS/PaaS/SaaS、Docker/Kubernetes 到 5G、Matter 與邊緣 AI——「計算」如何從本地搬到無處不在。

From IaaS/PaaS/SaaS, Docker/Kubernetes to 5G, Matter, and edge AI — how computation moved from desktops to everywhere.

概覽

為什麼「雲」改變了一切？

2006 年 AWS 推出 EC2 之前，新創公司要先花數十萬美元買伺服器、租機房、僱 SRE，才能上線。雲端讓「以分鐘計費、隨需擴充」成為現實——所有層次的基礎建設都變成可程式化資源：

  • IaaS（Infrastructure as a Service）：租 CPU/記憶體/網路（EC2、Azure VM、GCE）。
  • PaaS（Platform）：租「runtime + 資料庫」（Heroku、Cloud Run、Vercel）。
  • SaaS（Software）：直接用軟體（Gmail、Salesforce、Slack）。
  • FaaS / Serverless：只為「函數的每次執行」付費（AWS Lambda、Cloudflare Workers）。

2026 的常態是混合雲 (hybrid) 與多雲 (multi-cloud)——大型企業同時用 AWS、Azure、GCP，並把敏感資料留在私有資料中心。

Before AWS launched EC2 in 2006, a startup had to spend six figures on servers, colo, and ops before going live. The cloud turned infrastructure into pay-per-minute, on-demand, programmable resources across every layer:

  • IaaS: rent CPU / RAM / network (EC2, Azure VM, GCE).
  • PaaS: rent runtime + database (Heroku, Cloud Run, Vercel).
  • SaaS: use the software directly (Gmail, Salesforce, Slack).
  • FaaS / Serverless: pay per function invocation (AWS Lambda, Cloudflare Workers).

By 2026 the norm is hybrid and multi-cloud — large enterprises mix AWS, Azure, GCP, and keep sensitive workloads on private infrastructure.

💡
核心觀念：「The cloud is just someone else's computer」——這句俏皮話點出本質：雲端不是魔法，而是把計算、儲存、網路抽象成 API。便利的代價是「鎖定 (vendor lock-in)」與「成本失控」(2024 Cloud Optimization 報告：30% 雲端支出是浪費)。 Core idea: "The cloud is just someone else's computer." It's not magic — just compute/storage/network exposed as APIs. The trade-offs: vendor lock-in and runaway cost (FinOps 2024: ~30% of cloud spend is waste).

容器化與 K8s

二、Docker 與 Kubernetes

Docker (2013)：用 Linux namespaces + cgroups 把應用「打包」進可移植映像 (image)，啟動只需毫秒。相較 VM，容器共享 host 核心，啟動快、佔資源少。

Kubernetes (K8s, 2014 Google 開源)：容器數量上百上千時的編排系統。核心物件：

  • Pod：一或多個容器組成的最小部署單位。
  • Deployment：宣告「我要 5 個 Pod」，K8s 自動維持狀態。
  • Service：把一群 Pod 暴露為一個穩定的網路端點（內建負載平衡）。
  • HPA (Horizontal Pod Autoscaler)：依 CPU / 自訂指標自動擴縮 Pod 數。

Docker (2013): uses Linux namespaces + cgroups to package an app into a portable image; starts in milliseconds. Unlike VMs, containers share the host kernel — fast, lightweight.

Kubernetes (K8s, 2014 by Google): orchestrator for hundreds-to-thousands of containers. Core objects:

  • Pod: smallest deployable unit — one or more containers.
  • Deployment: declare "I want 5 Pods" and K8s reconciles.
  • Service: stable network endpoint fronting a set of Pods, with built-in load balancing.
  • HPA: auto-scales Pod count based on CPU or custom metrics.

⚠️
微服務 vs 單體：微服務 (microservices) 把系統拆成數十個獨立部署的小服務，每個服務只負責一件事。優點：團隊自治、可獨立擴展；缺點：分散式除錯困難、需要 service mesh (Istio / Linkerd) 做流量管理。2024 起出現「從微服務回歸 modular monolith」聲浪——Shopify、Amazon Prime Video 是知名案例。
Microservices vs monolith: microservices split a system into dozens of independently deployable services. Pros: team autonomy, independent scaling. Cons: distributed debugging is hard, needs a service mesh (Istio/Linkerd). Since 2024 the "back to modular monolith" backlash has grown — Shopify and Amazon Prime Video are notable examples.
邊緣運算與 IoT

三、CDN / 邊緣 / IoT

CDN / Edge Computing：把計算與快取放到「離使用者最近的節點」。Cloudflare、Fastly、AWS CloudFront 等業者在全球部署數百個 PoP（Point of Presence）。傳統來回美國西岸的延遲 50 ms，邊緣節點可降到 ~5 ms。

2026 主流範式：Cloudflare Workers、AWS Lambda@Edge、Vercel Edge Functions——在 V8 isolate 中於 100+ 個地理位置同時執行你的 JS / WASM 程式碼。

IoT 三層架構：

  1. 感測層：sensors + MCU (ESP32, Arduino, Raspberry Pi Pico)。
  2. 邊緣層：邊緣 AI (TinyML)、本地閘道。
  3. 雲端層：彙整、分析、模型訓練。

CDN / Edge Computing: push compute and cache to the user's nearest node. Cloudflare, Fastly, AWS CloudFront operate hundreds of global PoPs. A trip to US-West that used to cost 50 ms latency drops to ~5 ms at the edge.

2026 mainstream: Cloudflare Workers, AWS Lambda@Edge, Vercel Edge Functions — running your JS / WASM in V8 isolates across 100+ locations.

IoT three-tier architecture:

  1. Sensor tier: sensors + MCUs (ESP32, Arduino, RPi Pico).
  2. Edge tier: edge AI (TinyML), local gateway.
  3. Cloud tier: aggregation, analytics, model training.

5G 三大用例：① eMBB（增強型行動寬頻，1–10 Gbps）；② URLLC（超可靠低延遲通訊，1 ms 等級——自駕、遠距手術）；③ mMTC（大規模機器型通訊，每平方公里百萬連接——IoT 感測器）。6G 預計 2030 商用，目標亞毫秒延遲與 1 Tbps 峰值。

5G's three use cases: (1) eMBB (1–10 Gbps mobile broadband), (2) URLLC (1 ms latency — autonomy, remote surgery), (3) mMTC (millions of connections per km² — IoT). 6G is targeted for 2030 commercialization, aiming sub-ms latency and 1 Tbps peak.

部署選型

四、決策樹：選擇部署模式

🌳 該用 VM、Container 還是 Serverless？

Q1:
需要完整作業系統控制權（核心模組、特殊驅動）？→ 用 VM（EC2、Azure VM）。
Q2:
長時間運行的微服務、需要精確的擴縮控制？→ 用 Container + K8s（EKS、GKE、AKS）。
Q3:
事件驅動、流量不規則、短時間執行（< 15 分鐘）？→ 用 Serverless / FaaS（Lambda、Cloud Run、Workers）。
Q4:
全球低延遲（< 50 ms）？→ 用 Edge Functions（Cloudflare Workers、Vercel Edge）。
Q1:
Need full OS control (kernel modules, special drivers)? → Use VM (EC2, Azure VM).
Q2:
Long-running microservices with fine-grained scaling? → Container + K8s (EKS, GKE, AKS).
Q3:
Event-driven, spiky traffic, short executions (< 15 min)? → Serverless / FaaS (Lambda, Cloud Run, Workers).
Q4:
Global low-latency (< 50 ms)? → Edge Functions (Cloudflare Workers, Vercel Edge).

🌳 IoT：該用哪個通訊協定？

Q1:
低耗電、有 Wi-Fi、需要訂閱推播？→ MQTT（最主流）。
Q2:
記憶體 KB 等級、需要 REST 風格？→ CoAP。
Q3:
跨公里、田野部署、電池一次用 5 年？→ LoRaWAN。
Q4:
家用、需與 Apple/Google/Amazon 都互通？→ Matter。
Q1:
Low-power, has Wi-Fi, needs pub/sub push? → MQTT (most common).
Q2:
KB-scale memory, want REST-like? → CoAP.
Q3:
Multi-km range, field deployment, 5-year battery? → LoRaWAN.
Q4:
Smart home interop with Apple/Google/Amazon? → Matter.

    state = "Running"

        if liveness_probe.fails():

            service.remove_endpoint(pod)         // 從流量中暫時移除
        if hpa.should_scale_up():
            deployment.scale(+1)                // 水平擴展
    // 終止：先送 SIGTERM 給 30 秒 grace period，再 SIGKILL
