數位邏輯與布林代數

為什麼電腦能「思考」？因為所有運算——加減乘除、判斷比較、AI 推論——都可分解為 AND、OR、NOT 三個基本邏輯閘的組合。

Why can computers "think"? Because every operation — arithmetic, comparison, even AI inference — can be decomposed into combinations of AND, OR, NOT gates.

概覽

從電子開關到邏輯思維

1854 年，英國數學家 George Boole 在《思維法則的研究》中以 0/1（False/True）建立「布林代數」，將推理變成代數運算。八十多年後，Claude Shannon 在 1937 年 MIT 碩士論文中證明：可以用電子開關（繼電器、後來的電晶體）實作任何布林表達式——這篇論文常被譽為「20 世紀最重要的碩士論文」。

今天的 CPU 裡有數百億顆電晶體，全部都在做同一件事：執行 AND、OR、NOT。把它們堆疊組合，就能造出加法器、比較器、記憶單元，最終構成整台電腦。

In 1854, English mathematician George Boole founded "Boolean algebra" in An Investigation of the Laws of Thought, turning reasoning into algebra over 0/1 (False/True). Eighty-three years later, Claude Shannon's 1937 MIT master's thesis proved that electronic switches (relays, later transistors) can implement any Boolean expression — often called "the most important master's thesis of the 20th century."

Today's CPUs pack tens of billions of transistors, all doing the same thing: AND, OR, NOT. Stack them and you get adders, comparators, memory cells — an entire computer.

💡
核心觀念：邏輯閘是「輸入 0/1 → 輸出 0/1」的最小單元。每個閘的行為由真值表 (truth table) 完整定義，與電路實作無關。 Core idea: A logic gate is the smallest unit mapping 0/1 inputs to a 0/1 output. Its behavior is fully defined by a truth table, independent of physical implementation.

NAND universality: Any Boolean function can be built using only NAND gates — e.g., NOT A = A NAND A, A AND B = NOT(A NAND B). That's why NAND-gate arrays are the most mass-produced IC building blocks.

布林代數定律

三、布林代數五大定律

布林代數的化簡規則讓我們可以把複雜的邏輯式減化為更少的閘——這是邏輯閘合成 (logic synthesis) 的基礎，省晶片面積、降功耗。

Boolean simplification reduces complex expressions to fewer gates — the foundation of logic synthesis, saving die area and power.

半加器與全加器

四、半加器與全加器

單個位元的加法只有四種輸入組合，仔細看會發現：

  • 0+0 = 0（和=0，進位=0）
  • 0+1 = 1（和=1，進位=0）
  • 1+0 = 1（和=1，進位=0）
  • 1+1 = 10（和=0，進位=1）

和 (Sum) = A XOR B；進位 (Carry) = A AND B——這就是半加器 (Half Adder)。把兩個半加器再加一個 OR 閘串接，就能處理「上一位的進位」，成為全加器 (Full Adder)。把 32 個全加器串聯，便是 32-bit 整數加法器，CPU 裡的 ALU 核心。

Adding one bit at a time has only four cases:

  • 0+0 = 0 (sum=0, carry=0)
  • 0+1 = 1 (sum=1, carry=0)
  • 1+0 = 1 (sum=1, carry=0)
  • 1+1 = 10 (sum=0, carry=1)

Sum = A XOR B; Carry = A AND B — that's a half adder. Chain two half adders plus an OR gate to handle an incoming carry → full adder. Cascade 32 full adders and you have a 32-bit integer adder — the heart of every ALU.

情境選閘

五、情境選閘

🌳 邏輯閘選用決策樹

Q1:
「所有條件都需成立」→ 用 AND（例：權限檢查必須 login && admin && 2FA）。
Q2:
「任一條件成立即可」→ 用 OR（例：通知發送：email OR SMS OR push）。
Q3:
「兩者不同才有反應」→ 用 XOR（例：奇偶校驗、加密 one-time pad、差異檢測）。
Q4:
「兩者相等才放行」→ 用 XNOR（例：密碼比對、相等性檢測）。
Q5:
「想用最少種類閘做所有事」→ 全用 NAND 或全用 NOR（晶圓廠最愛）。
Q1:
"All conditions must hold" → use AND (e.g., permission = login && admin && 2FA).
Q2:
"Any one condition suffices" → use OR (e.g., notify via email OR SMS OR push).
Q3:
"Trigger when they differ" → use XOR (parity check, OTP encryption, diff detection).
Q4:
"Pass only when equal" → use XNOR (password compare, equality test).
Q5:
"Use the fewest gate types" → only NAND or only NOR (fab favorite).
🚨
常見錯誤：把短路求值 (&&) 與位元 AND (&) 混用！前者只回傳 true/false 且會短路；後者對所有位元逐一運算且兩邊都會求值。if (ptr && ptr->x) 是安全的，if (ptr & ptr->x) 會 segfault。
Common bug: Confusing short-circuit && with bitwise &. The former returns true/false and short-circuits; the latter operates per-bit and evaluates both sides. if (ptr && ptr->x) is safe; if (ptr & ptr->x) segfaults.

六、動手試

# 位元運算子 / Bitwise operators: & | ^ ~ << >>
a, b = 0b1100, 0b1010     # 12, 10
print(bin(a & b))    # 0b1000 (AND)
print(bin(a | b))    # 0b1110 (OR)
print(bin(a ^ b))    # 0b0110 (XOR)
print(bin(~a & 0xF))  # 0b0011 (NOT, 4-bit masked)

# 半加器 / Half adder
def half_adder(a, b):
    sum_bit = a ^ b           # XOR
    carry   = a & b           # AND
    return sum_bit, carry

# 全加器 / Full adder (a + b + cin)
def full_adder(a, b, cin):
    s1, c1 = half_adder(a, b)
    s2, c2 = half_adder(s1, cin)
    return s2, c1 | c2          # carry-out = OR of two carries

print(full_adder(1, 1, 1))  # (1, 1)  → 1+1+1 = 3 = 0b11

# De Morgan 驗證 / Verify De Morgan's law
for a in (0,1):
    for b in (0,1):
        assert (~(a & b) & 1) == ((~a & 1) | (~b & 1))
// 半加器 / Half Adder
function HalfAdder(A, B):
    Sum   = A XOR B
    Carry = A AND B
    return (Sum, Carry)

// 全加器 / Full Adder (handles carry-in)
function FullAdder(A, B, Cin):
    (S1, C1) = HalfAdder(A, B)
    (S2, C2) = HalfAdder(S1, Cin)
    return (S2, C1 OR C2)

// 32-bit 加法器 / 32-bit ripple-carry adder
function Add32(A[0..31], B[0..31]):
    let carry = 0
    let result = new bit[32]
    for i from 0 to 31:
        (result[i], carry) = FullAdder(A[i], B[i], carry)
    return result
