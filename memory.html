記憶體階層與儲存

為什麼一台電腦需要 6 種不同的儲存？因為「快、大、便宜」三者不可兼得。本章揭開金字塔結構、快取局部性與虛擬記憶體的設計巧思。

Why does one computer have six kinds of storage? Because "fast, big, cheap" cannot all coexist. This chapter unpacks the memory pyramid, cache locality, and virtual memory.

概覽

記憶體階層的根本矛盾

設計儲存系統有「不可能三角」：快、大、便宜三者頂多只能取兩個。SRAM 快但貴又小，磁帶大又便宜但慢得像蝸牛。工程師的解法是「分層」：把最常用的少量資料放在快速但小的層，整體資料放在慢但大的層。透過局部性原理，大多數存取都能命中最快的層。

2026 年一台典型電腦的速度差距：CPU 暫存器存取 < 1 ns，但讀 1 PB 磁帶可能要幾分鐘——9 個數量級的差異！

Storage systems have an "impossible triangle": you can pick at most two of fast / large / cheap. SRAM is fast but pricey and tiny; tape is huge and cheap but glacially slow. The engineering answer is the hierarchy: hot data in small fast layers, cold data in big slow layers. Thanks to locality of reference, most accesses hit the top.

The 2026 speed spread: a CPU register access takes < 1 ns, while reading 1 PB from tape can take minutes — 9 orders of magnitude.

💡
核心觀念：整個 OS 與 CPU 的「記憶體管理」其實是在玩「猜熱資料」的遊戲——猜對則快，猜錯則慢千百倍。 Core idea: OS and CPU memory management is essentially a game of "guess the hot data." A right guess is fast; a miss can be 100×–1000× slower.

Cache 設計核心

四、Cache 與局部性

Cache 之所以有效，靠的是「程式的存取模式並不隨機」這個經驗事實：

  • 時間局部性 (Temporal locality)：剛存取過的位址，很快又會被存取（如迴圈變數）。
  • 空間局部性 (Spatial locality)：剛存取的位址附近，很快也會被存取（如陣列走訪）。

因此 cache 一次搬「一條 cache line」(64 B)，不只搬目標位元組。Cache 的「關聯性 (associativity)」決定每條 line 能放哪幾個位置：direct-mapped 最快但衝突高、fully-associative 最靈活但硬體貴、現代 CPU 多用 4–16 way set-associative。

當資料不在 cache，就發生 cache miss，分為三大類（3C）：

Caches work because access patterns are not random:

  • Temporal locality: addresses just accessed are likely accessed again soon (e.g., loop counter).
  • Spatial locality: addresses near a recent access are likely next (e.g., array traversal).

So caches move a whole cache line (64 B), not just the target byte. Associativity sets how many lines can map to the same slot: direct-mapped is fastest but conflict-prone, fully-associative is flexible but expensive — modern CPUs use 4–16-way set-associative.

When data isn't in cache, you get a cache miss, in three classic flavors (the 3 Cs):

分頁與 MMU

五、虛擬記憶體

虛擬記憶體讓每個程式以為自己「獨占」整個 64-bit 位址空間，實際上：

  • 記憶體切成固定大小的 page（通常 4 KB；大頁 2 MB / 1 GB）。
  • Page Table 記錄「虛擬位址 → 物理位址」的對應，由 OS 維護。
  • MMU (Memory Management Unit) 是 CPU 內的硬體，每次存取自動查表轉址。
  • TLB (Translation Lookaside Buffer) 是 page table 的小型 cache（~64 條），讓常見轉址 < 1 ns。
  • 若 page 在 DRAM 中找不到 → Page Fault，OS 從 SSD 載入該 page（典型延遲：~100 µs，比 DRAM 慢 1000 倍）。

好處：① 程式隔離（A 程式無法看到 B 程式的記憶體）；② 可用空間 > 物理 RAM（用 SSD 作 swap）；③ 同一份程式碼可被多個程序共享。

Virtual memory makes every program believe it owns the entire 64-bit address space. In reality:

  • Memory is sliced into fixed-size pages (usually 4 KB; huge pages 2 MB / 1 GB).
  • The page table maps virtual → physical addresses, maintained by the OS.
  • The MMU (Memory Management Unit) is in-CPU hardware that does the translation on every access.
  • The TLB (Translation Lookaside Buffer) caches page-table entries (~64 entries), keeping common lookups < 1 ns.
  • If a page isn't in DRAM → page fault, OS loads it from SSD (~100 µs — 1000× slower than DRAM).

Benefits: (1) process isolation (program A can't see program B's memory); (2) addressable space > physical RAM (SSD swap); (3) shared code pages across processes.

儲存裝置演進

六、儲存裝置演進

HDD (1956+)

機械式磁碟，5400/7200 RPM 旋轉，磁頭讀寫。延遲 ~5 ms（seek + rotate）。容量大、單位成本最低，仍用於冷儲存與資料中心備份。

Spinning disk, 5400/7200 RPM, magnetic head. ~5 ms latency (seek + rotate). Big and cheap — still used for cold storage and data-center backups.

SATA SSD (2008+)

用 NAND Flash 取代磁片，無機械延遲。SATA 介面限制最高 ~600 MB/s。

NAND Flash replaces platters — no mechanical latency. SATA interface caps throughput at ~600 MB/s.

NVMe SSD (2015+) ⭐

直接走 PCIe 通道，2026 PCIe 5.0 可達 14 GB/s。延遲 ~50 µs，是 HDD 的 100 倍快。

Bypasses SATA, runs on PCIe. PCIe 5.0 (2026) hits 14 GB/s. Latency ~50 µs — 100× faster than HDD.

CXL Memory (2024+)

Compute Express Link 3.0：透過 PCIe 連接「記憶體擴充模組」，DRAM 容量可跨機架共享。AI 大型模型訓練的救星。

Compute Express Link 3.0: connect DRAM expansion modules over PCIe; capacity is poolable across racks. A lifesaver for large-model AI training.

八、動手試

# NumPy 預設為 row-major (C-order)：橫向掃描比直向掃描快很多
# NumPy default is row-major (C-order): scanning rows is much faster than columns
import numpy as np, time

N = 5000
a = np.ones((N, N), dtype='float32')   # 100 MB array

# 友善：沿 row 走，連續位址 → 命中 cache
# Friendly: walk along rows → contiguous addresses → cache hits
t = time.perf_counter()
s = 0.0
for i in range(N):
    for j in range(N):
        s += a[i, j]
print(f"Row-major:    {time.perf_counter()-t:.2f}s")

# 非友善：沿 column 走，每次跳 N*4 byte → 大量 cache miss
# Unfriendly: walk by column, stride N*4 bytes → many cache misses
t = time.perf_counter()
s = 0.0
for j in range(N):
    for i in range(N):
        s += a[i, j]
print(f"Column-major: {time.perf_counter()-t:.2f}s")
# Column 版通常慢 2–10 倍 / Column version is typically 2-10× slower

# 用向量化 (SIMD) 一次處理整個 row → 最快
# Vectorized (SIMD) processes whole rows at once — fastest
t = time.perf_counter()
s = a.sum()
print(f"Vectorized:   {time.perf_counter()-t:.3f}s")
// Cache-blocking 矩陣乘法 / Cache-blocked matrix multiplication
function MatMulBlocked(A, B, C, N, BLOCK):
    for ii from 0 to N step BLOCK:
        for jj from 0 to N step BLOCK:
            for kk from 0 to N step BLOCK:
                // 在 BLOCK×BLOCK 子矩陣內完成全部乘加，
                // 讓子矩陣完全裝進 L1 / L2 cache
                for i from ii to min(ii+BLOCK, N):
                    for j from jj to min(jj+BLOCK, N):
                        for k from kk to min(kk+BLOCK, N):
                            C[i][j] += A[i][k] × B[k][j]
    return C
// BLOCK 通常選 64 或 128，視 L1 大小調整
// Typical BLOCK = 64 or 128, tuned to L1 size
