作業系統

作業系統是硬體與應用程式之間的「翻譯層」——管理 CPU、記憶體、檔案、I/O，並提供行程、執行緒、虛擬化等抽象。

An OS is the translation layer between hardware and applications — it manages CPU, memory, files, and I/O, and exposes abstractions like processes, threads, and virtualization.

概覽

OS 為何不可或缺？

沒有作業系統，每個程式都得自己驅動硬碟、配置記憶體、處理鍵盤中斷——既不安全也不可移植。OS 的核心使命是把混亂的硬體包成乾淨的 API（系統呼叫 syscall），並仲裁多個程式同時競爭資源時的公平性與正確性。

從手錶上的 watchOS、手機 Android/iOS、桌面 Windows/macOS/Linux，到資料中心的 Linux + Kubernetes，每個現代計算裝置都仰賴 OS。

Without an OS, every program would have to drive the disk, allocate memory, and handle keyboard interrupts itself — unsafe and non-portable. The OS's core mission is to wrap chaotic hardware into clean APIs (system calls) and arbitrate fairness and correctness when many programs compete for resources.

From watchOS on a wristwatch, Android/iOS on phones, Windows/macOS/Linux on desktops, to Linux + Kubernetes in data centers — every modern device depends on an OS.

💡
核心觀念：OS 的兩大角色是「資源管理者」（公平分配 CPU/RAM/I/O）與「抽象層」（提供檔案、行程、socket 等概念，隱藏硬體細節）。 Core idea: An OS plays two roles — resource manager (fairly allocate CPU/RAM/I/O) and abstraction layer (expose files, processes, sockets — hiding hardware details).

行程與執行緒

二、Process vs Thread

行程 (Process) 是「正在執行中的程式」——擁有獨立的位址空間、檔案描述符、PID。執行緒 (Thread) 是行程內的執行單位，共享同一份記憶體與檔案，但有自己的暫存器與堆疊。

fork() 複製整個父行程；exec() 載入新程式覆蓋目前位址空間。Linux 用 PCB (Process Control Block) 紀錄行程狀態；切換行程時必須儲存/還原所有暫存器，這就是 context switch，成本約 1–10 μs（執行緒切換約 1 μs，行程切換更貴因為要刷新 TLB）。

A process is a "program in execution" with its own address space, file descriptors, and PID. A thread is an execution unit inside a process — sharing memory and files but having its own registers and stack.

fork() duplicates the parent process; exec() loads a new program over the current address space. Linux uses a PCB (Process Control Block) to track state. Switching processes requires saving/restoring all registers — the context switch, costing 1–10 μs (threads ~1 μs; processes cost more because the TLB must be flushed).

同步與鎖

五、同步與死結

多執行緒共享記憶體時，若兩個執行緒同時讀寫同一變數，會出現 競態 (race condition)。OS 提供兩大同步原語：

  • Mutex（互斥鎖）：同一時間只有 1 個執行緒能持有，常用於保護臨界區。
  • Semaphore（號誌）：計數器，允許 N 個執行緒同時通過——可實作生產者-消費者問題。

死結 (Deadlock) 需同時滿足四條件，破壞任一條即可避免：

When threads share memory, simultaneous reads/writes cause race conditions. OSes provide two synchronization primitives:

  • Mutex: held by exactly one thread at a time — protects critical sections.
  • Semaphore: a counter allowing N concurrent threads — used in producer-consumer.

Deadlock requires all four conditions simultaneously — break any one to prevent it:

🌳 Deadlock 四條件

①
互斥 (Mutual exclusion) → 資源同時只能被一個行程持有。
②
持有並等待 (Hold and wait) → 行程持有資源時還能等待新資源。
③
不可搶佔 (No preemption) → 資源不能被強制收回。
④
循環等待 (Circular wait) → 形成「行程 A 等 B 等 C 等 A」的環。
①
Mutual exclusion → resources held exclusively.
②
Hold and wait → processes hold while waiting for more.
③
No preemption → resources cannot be forcibly taken back.
④
Circular wait → A waits B waits C waits A — a cycle.

虛擬化與容器

七、虛擬機 vs 容器

🌳 VM vs Container 決策樹

Q1:
需執行「不同 OS」（如 Windows app on Linux）？→ 是 → 用 VM（VMware / KVM / Hyper-V）。
Q2:
需「秒級啟動 + 高密度部署」（一台機跑 100 個服務）？→ 是 → 用 Container（Docker / containerd）。
Q3:
跨多台機器編排調度？→ 是 → Kubernetes（容器 + 自動擴展 + 自癒）。
Q4:
需強隔離（多租戶、敵對工作負載）？→ 是 → VM 或 gVisor / Firecracker 微 VM。
Q1:
Run a different OS (e.g. Windows app on Linux)? → Yes → VM (VMware / KVM / Hyper-V).
Q2:
Need sub-second startup + high-density deploy (100 services per host)? → Yes → Container (Docker / containerd).
Q3:
Orchestrate across many hosts? → Yes → Kubernetes (containers + autoscale + self-healing).
Q4:
Need strong isolation (multi-tenant)? → Yes → VM or microVM (gVisor / Firecracker).
⚠️
關鍵差別：VM 虛擬化整台機器（含 guest kernel），容器只虛擬化 OS 介面（共享 host kernel）。VM 開機 ~30 秒、印象 GB 級；容器啟動 ~100 ms、印象 MB 級。
Key difference: A VM virtualizes the whole machine (with its own guest kernel); a container virtualizes only the OS interface (sharing the host kernel). VM boots in ~30 s, images in GB; containers start in ~100 ms with MB images.

九、threading 與 multiprocessing

# 執行緒適合 I/O 密集；多行程適合 CPU 密集（Python 有 GIL）
# Threads: I/O-bound. Processes: CPU-bound (Python has the GIL).
import threading, multiprocessing, time

def cpu_work(n):
    s = 0
    for i in range(n): s += i*i
    return s

# 4 個執行緒——受 GIL 限制，CPU 工作不會加速
ts = [threading.Thread(target=cpu_work, args=(10_000_000,)) for _ in range(4)]
[t.start() for t in ts]; [t.join() for t in ts]

# 4 個行程——真正並行（每個有自己的 Python interpreter）
with multiprocessing.Pool(4) as p:
    p.map(cpu_work, [10_000_000]*4)

# Mutex 保護共享計數器 / Mutex protects shared counter
lock = threading.Lock()
counter = 0
def inc():
    global counter
    with lock:
        counter += 1     # 臨界區 / critical section
// 生產者-消費者問題 (semaphore 解) / Producer-Consumer with semaphores
let buffer = []        // 有界佇列，容量 N
let empty = Sem(N)     // 還剩多少空位
let full  = Sem(0)     // 已放入多少項目
let mutex = Mutex()

function Producer():
    while true:
        item = make_item()
        empty.wait()              // 等空位
        mutex.lock()
        buffer.push(item)
        mutex.unlock()
        full.signal()             // 通知消費者

function Consumer():
    while true:
        full.wait()               // 等項目
        mutex.lock()
        item = buffer.pop()
        mutex.unlock()
        empty.signal()            // 釋放空位
        consume(item)
