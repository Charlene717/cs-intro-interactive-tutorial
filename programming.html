程式設計入門

從 1957 年 Fortran 把人類從機器碼解放，到 2026 年用自然語言就能 vibe coding——程式語言是人類意圖與機器指令之間最重要的橋樑。本章從零帶你看懂程式語言的世界。

From Fortran liberating humans from machine code in 1957 to vibe-coding in natural language in 2026 — programming languages are the most important bridge between human intent and machine instructions. This chapter walks you through it from zero.

兩次語言革命

從打孔卡到自然語言：兩次「程式革命」

1957 年的某個午後，IBM 的 John Backus 領導的小組終於讓 Fortran 編譯器 在 IBM 704 上跑通。在此之前，所有人都得寫機器碼或組合語言——一行錯就要花一週 debug。Fortran 出現後，一個科學家寫一個工程公式，只要按一個鍵，編譯器自動生成上百行機器碼。從此「寫程式」不再只是電機博士的工作，而是普通職業。

2022 年 11 月 30 日，OpenAI 發布 ChatGPT。3 年後 (2026 年)，Claude Code、Cursor、Copilot 已能根據一句「幫我寫一個 FASTQ 品質過濾腳本」直接產出可執行的 Python。第二次革命：自然語言本身成為新的「程式語言」。但這也意味著——真正讀懂程式碼、能 debug、能審查 AI 產出的人，價值反而更高。

這一章不只教你「Python 怎麼寫迴圈」。它要回答：為什麼 2026 年的生物資訊學家仍要同時學 Python 和 R？什麼時候該用 Rust？LLM 寫的程式碼真的能信嗎？

On an afternoon in 1957, John Backus's IBM team finally got the Fortran compiler running on the IBM 704. Before that, everyone wrote machine code or assembly — one typo cost a week of debugging. With Fortran, a scientist could write an engineering formula, press a key, and the compiler emitted hundreds of machine instructions automatically. From that day, "programming" stopped being only for EE PhDs and became an ordinary profession.

November 30, 2022 — OpenAI launched ChatGPT. Three years later (2026), Claude Code, Cursor, and Copilot can produce runnable Python from a sentence like "write me a FASTQ quality filter." The second revolution: natural language itself is becoming a programming language. But this also means people who can actually read code, debug, and review LLM output become more valuable, not less.

This chapter isn't just "how to write a for-loop in Python." It answers: why must a 2026 bioinformatician learn both Python and R? When should you reach for Rust? Can you trust LLM-generated code?

💡
核心觀念：不存在「最好」的語言，只有「最合適」的語言。每種語言都是一組取捨——速度 vs 可讀性、安全 vs 自由、新潮 vs 生態。學會「為情境挑工具」，比學會單一語言重要十倍。 Core idea: There is no "best" language, only the "right" one. Every language is a set of trade-offs — speed vs readability, safety vs freedom, novelty vs ecosystem. Learning to pick the right tool for the context is 10× more valuable than mastering any single language.
核心：初學者必懂

一、初學者必懂的六個核心概念

📦

變數與型別

變數是「貼了名字的記憶體格子」。x = 42 把整數 42 存進名為 x 的格子。型別告訴電腦這個值是整數、字串、還是浮點數——不同型別佔不同記憶體、能做不同操作。

A variable is "a labeled memory slot." x = 42 stores 42 under the name x. The type tells the computer what's inside — int, string, float — affecting memory usage and operations.

🔀

控制流

程式不是只能「從上往下」執行。if / else 讓程式做選擇；for / while 讓程式重複；break / continue 讓程式跳出。控制流是「邏輯」的語法化。

Programs don't only flow top-to-bottom. if/else chooses, for/while repeats, break/continue escapes. Control flow is "logic made into syntax."

🛠️

函式

把一段邏輯包成「可呼叫的小機器」，給輸入、拿輸出。函式是「重複利用」與「思考分塊」的基石。DRY 原則：Don't Repeat Yourself。

Bundle logic into "callable mini-machines": inputs in, outputs out. Functions are the foundation of reuse and abstraction. DRY: Don't Repeat Yourself.

🧱

OOP 四大支柱

封裝：把 state 藏在物件裡。繼承：Dog 繼承 Animal 的 name 屬性。多型：dog.speak() 和 cat.speak() 同名但不同行為。抽象：用 interface 隱藏實作細節。

Encapsulation: hide state. Inheritance: Dog inherits name from Animal. Polymorphism: dog.speak() and cat.speak() same name, different behavior. Abstraction: hide details behind interfaces.

🔁

編譯 vs 直譯 vs JIT

編譯式 (C/Rust/Go)：一次轉成機器碼，跑得快。直譯式 (Python/Ruby)：逐行翻譯，啟動快。JIT (Java/JS)：先變位元碼，熱點動態優化。三者邊界越來越模糊。

Compiled (C/Rust/Go): all to machine code up front — fast. Interpreted (Python/Ruby): line by line — fast startup. JIT (Java/JS): bytecode + runtime optimization. The lines are blurring.

📜

五大典範

Imperative (step-by-step)、OOP (物件)、Functional (純函式)、Logic (規則)、Declarative (描述目標)。多數現代語言混用多種典範。

Imperative (step-by-step), OOP (objects), Functional (pure functions), Logic (rules), Declarative (describe goals). Modern languages mix multiple paradigms.

進階：型別系統

三、深入剖析：型別系統與 GIL

3.1 靜態型別 vs 動態型別

靜態型別：變數型別在編譯期就確定 (C/Java/Rust/TypeScript)。優點：編譯器早早抓錯、IDE 自動補全強、效能好。缺點：寫起來囉嗦。

動態型別：型別在執行期決定 (Python/JavaScript/Ruby)。優點：靈活、寫得快、適合探索式分析。缺點：執行到那一行才發現錯誤、IDE 補全弱。

2026 趨勢：「漸進式型別 (Gradual Typing)」。Python 從 3.5 起加入 type hints，TypeScript 是「JavaScript + 型別」，Ruby 加入 RBS，PHP 8 加入嚴格型別。動態語言全面「補課」型別檢查。

Static typing: types fixed at compile time (C/Java/Rust/TypeScript). Pro: compiler catches errors early, IDE autocomplete is strong, performance is good. Con: verbose.

Dynamic typing: types determined at runtime (Python/JavaScript/Ruby). Pro: flexible, fast to write, great for exploratory analysis. Con: errors caught only when that line runs.

2026 trend: gradual typing. Python added type hints in 3.5, TypeScript = "JS + types," Ruby added RBS, PHP 8 added strict types. Dynamic languages are all retrofitting type checking.

3.2 強型別 vs 弱型別

易混淆！強型別指型別轉換需要明示（Python: "3" + 5 直接報錯）；弱型別則默默隱式轉換（JavaScript: "3" + 5 === "35"）。Python 是「動態 + 強」，C 是「靜態 + 弱」（指標可任意轉型），Rust 是「靜態 + 強」（最嚴格）。

Often confused! Strong typing: explicit conversion required (Python: "3" + 5 → error). Weak typing: silent implicit coercion (JS: "3" + 5 === "35"). Python is "dynamic + strong," C is "static + weak" (pointers cast freely), Rust is "static + strong" (strictest).

3.3 Python GIL 與 3.13 的歷史性改變

長期以來，Python 有一個惡名昭彰的 GIL (Global Interpreter Lock，全域直譯器鎖)：同一時間只有一個執行緒能執行 Python bytecode。這讓 Python 多執行緒在 CPU 密集任務上幾乎無加速效果，必須用 multiprocessing 開多個 process（記憶體開銷大）才能用滿多核心。

2024 年 10 月發布的 Python 3.13 引入了實驗性的 free-threading (PEP 703)，可編譯為 --disable-gil 的版本！這是 Python 30 年來最大的執行模型變革。雖然單執行緒效能略降（~10%），但多核心擴展性大幅提升——對 NumPy、scikit-learn、Scanpy 等科學運算意義重大。

Notoriously, Python has the GIL (Global Interpreter Lock): only one thread executes Python bytecode at a time. This makes Python multithreading useless for CPU-bound work — you have to use multiprocessing with multiple processes (heavy memory overhead) to use multiple cores.

Python 3.13 (October 2024) introduced experimental free-threading (PEP 703) — a build option --disable-gil! This is the biggest execution-model change in Python's 30+ year history. Single-thread perf drops ~10%, but multi-core scaling is transformative — huge for NumPy/scikit-learn/Scanpy.

3.4 型別提示與靜態檢查工具

Python 3.5+ 加入 type hints：def add(x: int, y: int) -> int:。執行期不檢查，但配合 mypy / pyright / ty 工具可在 commit 前抓錯。Astral 2026 發布的 ty (Rust 寫的) 比 mypy 快 100×，成為新主流。

Python 3.5+ supports type hints: def add(x: int, y: int) -> int:. Not checked at runtime, but with mypy / pyright / ty they catch errors before commit. Astral's ty (Rust-based, 2026) is 100× faster than mypy and is becoming the new default.

語言歷史：6 個改變世界的故事

四、改變世界的 6 個故事

① Grace Hopper & A-0 (1952)

美國海軍少將 Grace Hopper 1952 年寫出史上第一個編譯器 A-0，能把符號指令轉成 UNIVAC I 機器碼。她跟長官說「電腦可以懂英文」，被嘲笑「電腦只會數學」。三年後她基於 A-0 設計了 FLOW-MATIC，成為 COBOL 的前身。她也是「bug」一詞的傳播者——1947 年 Mark II 電腦真的找到一隻蛾。

Rear Admiral Grace Hopper wrote the first compiler A-0 for UNIVAC I in 1952. She told her bosses "computers can understand English" — and was mocked: "computers only do math." Three years later her FLOW-MATIC (built on A-0) became the ancestor of COBOL. She also popularized the word "bug" — a moth literally got stuck in the Mark II in 1947.

② COBOL (1959): 至今仍在跑

1959 年由 Hopper 等人主導設計的 COBOL 至今仍在運轉——估計 2026 年全球 43% 的銀行系統、95% 的 ATM、和大多數美國政府主機都跑著 COBOL。Y2K (2000) 前後 COBOL 程式設計師時薪暴漲到 200 USD；2020 年新澤西州因失業金系統 COBOL 故障，州長公開徵求「會 COBOL 的程式設計師」。

Designed in 1959 (with Hopper's leadership), COBOL still runs today — estimated 2026: 43% of global banking, 95% of ATMs, and most US government mainframes. Around Y2K (2000), COBOL devs commanded $200/hr; in 2020 New Jersey's governor publicly begged for COBOL programmers when the unemployment system broke.

③ Python (1991): 聖誕假期創作

1989 年聖誕節，荷蘭 CWI 研究員 Guido van Rossum 為了打發無聊，開始寫一個「ABC 語言的進階版」。語言名稱來自他喜歡的英國喜劇 Monty Python。1991 年 2 月公開首版。30 年後它成為全世界最熱門的語言。Guido 2018 卸任 BDFL，2020 加入微軟 Python 加速團隊。

Christmas 1989, CWI researcher Guido van Rossum started writing "an improved ABC language" to kill time. He named it after the British comedy Monty Python. First public release February 1991. Thirty years later it's #1. Guido stepped down as BDFL in 2018, joined Microsoft's Python performance team in 2020.

④ JavaScript (1995): 10 天寫成

1995 年 5 月，Netscape 雇用 Brendan Eich，要他「兩週內寫出一個可以在瀏覽器跑的腳本語言」。Eich 用 10 天 寫出了 JavaScript 原型——這也是它早期 quirks 多到出名的原因（[] + [] === ""、typeof null === "object"）。但今天全球 98% 網頁靠它運作。

May 1995, Netscape hired Brendan Eich: "write a browser scripting language in two weeks." Eich finished JS in 10 days — which is why it has so many famous quirks ([] + [] === "", typeof null === "object"). Yet today 98% of the web runs on it.

⑤ Rust (2010): 從 Mozilla 到 Linux kernel

Graydon Hoare 2006 年在 Mozilla 內部開始寫 Rust，受夠了 Firefox 的 C++ 記憶體 bug。2010 公開、2015 1.0。2022 Linux kernel 接受 Rust 成為 C 之外第二個官方語言——這是 30 年來首次。AWS、Microsoft、Cloudflare、Discord 都在大量使用。Stack Overflow 連續 8 年「最受愛戴的語言」。

Graydon Hoare began Rust internally at Mozilla in 2006, fed up with Firefox C++ memory bugs. Public in 2010, 1.0 in 2015. In 2022, the Linux kernel accepted Rust as a second official language alongside C — the first such addition in 30 years. AWS, Microsoft, Cloudflare, Discord use it heavily. Stack Overflow's "most loved language" for 8 straight years.

⑥ Mojo (2023): 為 AI 而生的 Python 超集

2023 年 LLVM/Swift 之父 Chris Lattner 創辦 Modular AI，發表 Mojo——一個 Python 超集 (super-set) 但能編譯成原生機器碼。對特定數值運算可達 35,000× Python 速度。2024 年開源。目標：取代 CUDA 成為 AI 加速器跨平台語言。

In 2023, Chris Lattner (creator of LLVM/Swift) founded Modular AI and released Mojo — a Python super-set that compiles to native code. Up to 35,000× Python speed on numerical workloads. Open-sourced 2024. Goal: replace CUDA as the cross-platform AI-accelerator language.

🧬 給生物資訊學家

六、🧬 生資連結：Python + R 雙修 + 5 種語言的位置

真實的生資工作流，幾乎沒人能只用一種語言。 從 FASTQ 到報告，至少要動用 3 種：

1. Python（資料科學與 AI 的事實標準）

Python 在生資的兩大支柱：Scanpy (單細胞 RNA-seq、Wolf 2018 Genome Biology)、scikit-learn (機器學習)、PyTorch (深度學習，AlphaFold 2 / Geneformer / scGPT 都用)。NumPy + pandas + matplotlib 是任何 EDA 的起點。

2. R（生物統計與 Bioconductor 的家園）

R 的優勢：Bioconductor 收錄 2,200+ 套件 (2026)，從 RNA-seq (DESeq2 Love 2014, edgeR) 到單細胞 (Seurat Hao 2023)、空間轉錄組 (Visium/Squidpy)、流式 (flowCore)。統計學家寫的套件多用 R。tidyverse (Wickham 2019) 讓資料處理變優雅。

3. Julia (新興：高效能科學計算)

Julia 在計算系統生物學日益重要。Catalyst.jl + DifferentialEquations.jl 是世界級的反應網路與 ODE 模擬器。JuliaCall 讓 R/Python 也能呼叫 Julia。速度接近 C 但語法接近 Python。

4. Rust（新興：效能關鍵的 bio 工具）

rust-htslib 是 Rust 版的 BAM/VCF 處理。新工具像 nanopolish 的繼承者、fgbio 的某些模組、varlociraptor 都用 Rust。speed 是 Python 的 10–100×，記憶體安全是 C++ 沒有的。

5. MATLAB（影像分析的歷史地位）

CellProfiler 早期版本 (2005) 用 MATLAB，後改寫 Python。Image Processing Toolbox 仍是顯微鏡影像的傳統工具。學界 license 普遍可用，但年輕一代多轉向 Fiji/ImageJ (Java) + Python (scikit-image, cellpose Stringer 2025 Nat Methods)。

6. Shell scripting (Bash + awk + sed)：bioinformatician 的必備

沒有 Bash 就沒有生物資訊。samtools view file.bam | awk '$5 > 30' | wc -l 是日常。GNU Parallel 把單核心腳本平行化。Snakemake / Nextflow 的底層也是 shell。

Real bioinformatics workflows almost never use just one language. From FASTQ to report, you'll touch at least 3:

1. Python (the de-facto data-science + AI standard)

Two pillars: Scanpy (single-cell RNA-seq, Wolf 2018 Genome Biology), scikit-learn, PyTorch (used by AlphaFold 2, Geneformer, scGPT). NumPy + pandas + matplotlib are any EDA's starting point.

2. R (home of biostatistics & Bioconductor)

R's edge: Bioconductor hosts 2,200+ packages (2026) — RNA-seq (DESeq2 Love 2014, edgeR), single-cell (Seurat Hao 2023), spatial (Visium/Squidpy), flow (flowCore). Statistician-authored packages favor R. tidyverse (Wickham 2019) makes data work elegant.

3. Julia (rising: high-performance scientific computing)

Big in systems biology. Catalyst.jl + DifferentialEquations.jl are world-class ODE/reaction-network engines. JuliaCall bridges R/Python. C-class speed with Python-class syntax.

4. Rust (rising: performance-critical bio tools)

rust-htslib handles BAM/VCF in Rust. Newer tools like successors to nanopolish, parts of fgbio, and varlociraptor are Rust. 10–100× Python speed, memory-safe unlike C++.

5. MATLAB (historical role in image analysis)

CellProfiler's early version (2005) was MATLAB before moving to Python. The Image Processing Toolbox remains a traditional microscopy tool, but the next generation prefers Fiji/ImageJ (Java) + Python (scikit-image, cellpose Stringer 2025 Nat Methods).

6. Shell scripting (Bash + awk + sed): the bioinformatician's daily bread

No Bash, no bioinformatics. samtools view file.bam | awk '$5 > 30' | wc -l is everyday. GNU Parallel parallelizes single-core scripts. Snakemake/Nextflow ultimately call shell underneath.

🎯
建議學習順序：① Python 打底（語法、pandas、scikit-learn）→ ② R + Bioconductor（DESeq2、Seurat）→ ③ Bash + Snakemake → ④ 進階用 Rust 寫熱點，或 Julia 模擬 ODE。不要追求「精通一種」就好，要的是「能讀懂、能改、能組合」3–4 種。
Recommended path: (1) Python foundation (syntax, pandas, scikit-learn) → (2) R + Bioconductor (DESeq2, Seurat) → (3) Bash + Snakemake → (4) advanced: Rust for hot paths, Julia for ODEs. Don't aim to "master one" — aim to "read, edit, and combine" 3–4 of them.

八、動手寫：階乘 + OOP 三語

# Python 3.13: 階乘 + OOP / Factorial + OOP
from functools import reduce

# 1. 遞迴 / Recursive
def factorial(n: int) -> int:
    if n <= 1: return 1
    return n * factorial(n - 1)

# 2. 函數式 / Functional (reduce)
fact_fn = lambda n: reduce(lambda a,b: a*b, range(1, n+1), 1)

# 3. OOP: Encapsulation + Inheritance + Polymorphism
class Animal:
    def __init__(self, name: str):
        self._name = name             # 封裝：private-ish
    def speak(self) -> str:
        return "..."

class Dog(Animal):                  # 繼承
    def speak(self):              # 多型
        return f"{self._name} says Woof!"

for a in [Dog("Rex"), Animal("X")]:
    print(a.speak())
# R: 階乘 + S4 OOP / Factorial + S4 OOP
# 1. 遞迴
factorial <- function(n) {
  if (n <= 1) return(1)
  n * factorial(n - 1)
}

# 2. 函數式 (Reduce)

scverse 多語整合的真實案例

八-B、scverse 三語整合案例

2025 年 scverse consortium (Virshup et al., Nature Biotechnology 2023) 已成為單細胞分析事實標準。它的價值不是「另一個 Scanpy」，而是 把 Python + R + Rust 的優勢縫在一起：

  • 核心 Python 套件：anndata（資料結構）、scanpy（分析）、scvi-tools（深度學習）、squidpy（空間轉錄組）——選 Python 是因為深度學習與 NumPy 生態無敵。
  • R 互通層：anndata2ri、zellkonverter（Bioconductor）——可把 AnnData 物件無痛在 Seurat / SingleCellExperiment 之間轉換。這讓使用者可在 DESeq2 + Seurat 的 R 工作流跟 scvi-tools + Scanpy 的 Python 工作流間自由切換。
  • Rust 加速：anndata-rs（讀寫加速 5×）、scirpy 的核心比對引擎、未來的稀疏矩陣引擎都計畫用 Rust。
  • 容器化：scverse 提供官方 Docker image，整個 stack（含 GPU drivers）一行 docker pull。
  • 標準格式：.h5ad + .zarr（雲端原生），可跑 100 萬細胞 in-memory，也可遠端 lazy load 1000 萬細胞。

這個案例的啟示：① 真正成功的科學軟體生態系都是「多語混用」；② Python 作 glue、R 作統計、Rust 作 hot path —— 各司其職；③ 互通性 (interoperability) 比效能更重要——別人能輕鬆讀寫你的資料格式，比你的工具快 10% 更有價值。

By 2025, the scverse consortium (Virshup et al., Nature Biotechnology 2023) became the de facto single-cell standard. Its real value isn't being "another Scanpy" — it's stitching together Python + R + Rust strengths:

  • Core Python packages: anndata (data structure), scanpy (analysis), scvi-tools (deep learning), squidpy (spatial). Python was chosen because its DL + NumPy ecosystem is unmatched.
  • R interop layer: anndata2ri, zellkonverter (Bioconductor) — convert AnnData ↔ Seurat / SingleCellExperiment seamlessly. Users move freely between DESeq2 + Seurat (R) and scvi-tools + Scanpy (Python).
  • Rust acceleration: anndata-rs (5× faster I/O), scirpy's matching engine, future sparse-matrix engines planned in Rust.
  • Containerization: scverse ships official Docker images — whole stack (incl. GPU drivers) in one docker pull.
  • Standard formats: .h5ad + .zarr (cloud-native) — 1M cells in-memory, 10M cells via remote lazy loading.

Takeaways: (1) every truly successful scientific software ecosystem is multi-language; (2) Python as glue, R for stats, Rust for hot paths — different jobs; (3) interoperability matters more than performance — letting others read your format easily is worth more than being 10% faster.

常見誤解

九、常見誤解

❌ 「Python 慢，不能做科學運算」

純 Python 確實慢，但 NumPy (C/Fortran 底層)、Numba (JIT)、Cython、JAX 把熱點降到接近 C 的速度。Scanpy 處理 100 萬細胞只要分鐘級——背後是高度向量化的 NumPy/scipy。

Pure Python is slow, but NumPy (C/Fortran inside), Numba (JIT), Cython, JAX bring hot paths near C speed. Scanpy processes 1M cells in minutes thanks to heavily-vectorized NumPy/scipy.

❌ 「OOP 是唯一範式」

Java 1990 年代讓全世界以為「程式設計 = OOP」。但 functional 在資料管線、declarative 在 SQL/HTML、imperative 在嵌入式都更合適。pandas / dplyr / Spark 都重度借鏡 FP。

1990s Java made the world think "programming = OOP." But functional is better for data pipelines, declarative for SQL/HTML, imperative for embedded. pandas / dplyr / Spark all heavily borrow from FP.

❌ 「會 ChatGPT 寫程式就不用學了」

LLM 寫的程式 30%+ 有錯 (Anthropic 2025 內部評估)。你需要懂程式才能審查、debug、判斷它有沒有亂編 API。真正的能力是「快速讀懂並驗證」，這恰好是 LLM 還做不好的事。

LLM-written code is wrong 30%+ of the time (Anthropic 2025 internal eval). You need to read, debug, and detect hallucinated APIs. The real skill is "read & verify fast" — which LLMs still can't do well.

❌ 「型別提示拖慢執行」

Python 的 type hints 執行期不檢查，只是給 mypy/pyright/IDE 用的注解。對效能零影響，反而讓編輯器補全與重構更強大。

Python type hints are not checked at runtime — they're annotations for mypy/pyright/IDEs. Zero perf impact, plus much better autocomplete & refactoring.

記憶體管理三大派

九-A、記憶體管理三大派系

「誰負責釋放記憶體？」這個問題分裂了整個程式語言世界，演變出三大派別：

"Who frees memory?" — this question fractured the programming-language world into three schools:

🧹

① 手動（C/C++）

程式員自己 malloc/free、new/delete。最快、最自由，但 memory leak、use-after-free、double-free 是無止盡的 bug 源。Heartbleed (2014) 與大量 CVE 都源自此類錯誤。C++ 11 起的 smart pointer（unique_ptr、shared_ptr）是部分補救。

You malloc/free yourself. Fastest, most flexible, but memory leaks, use-after-free, and double-free are endless bug sources. Heartbleed (2014) and countless CVEs come from this. C++11's smart pointers (unique_ptr / shared_ptr) are partial mitigation.

♻️

② GC（Java/Python/Go/JS/R）

runtime 自動偵測「無人引用」的物件並回收。主流演算法：tracing GC（mark-sweep、generational、G1）與 reference counting（Python CPython 主用 RC + cycle detector）。優：開發效率高、無記憶體錯誤。缺：暫停 (GC pause) 影響低延遲應用、記憶體膨脹。Go 把 GC pause 壓到 < 1ms 是工程奇蹟。

The runtime detects unreachable objects and reclaims them. Two big families: tracing GC (mark-sweep, generational, G1) and reference counting (CPython is RC + cycle detector). Pro: high productivity, no memory errors. Con: GC pauses hurt low-latency apps, memory bloat. Go shrinking GC pauses below 1 ms is an engineering marvel.

🔒

③ Ownership（Rust）

Rust 的第三條路：編譯期就解決——每個值「只能有一個 owner」，owner 離開 scope 即釋放。借用 (&) 規則 + lifetime 由 borrow checker 在編譯期驗證。無 GC、無 memory bug。代價：學習曲線陡，但一旦學會，bug 大幅減少。Linux kernel 2022 起接受 Rust。

Rust's third way: solve it at compile time — each value has one owner; freed when the owner leaves scope. Borrowing (&) rules + lifetimes are verified by the borrow checker. No GC, no memory bugs. Cost: steep learning curve, but bugs collapse once learned. Linux kernel accepted Rust in 2022.

⚠️
對生資的啟示：處理 100 GB BAM/VCF 時，GC 的暫停可能讓 8 小時的 job 多花 1 小時；Python 的 reference counting 在循環引用時還可能 leak。Rust 的 rust-htslib、htsget 等工具受惠於 ownership：可預測的記憶體曲線 + 無 GC 抖動。
For bioinformatics: When processing 100 GB BAM/VCF, GC pauses can add an hour to an 8-hour job; Python reference counting may even leak on cycles. Rust tools (rust-htslib, htsget) benefit from ownership: predictable memory curves with no GC jitter.

並行模型四大流派

九-C、並行四大模型

① OS Threads + Locks

POSIX pthread、Java Thread、Python threading。每 thread 是 OS 排程單位，共享記憶體要靠 mutex / semaphore。陷阱：deadlock、race condition、priority inversion。Python 因 GIL 在 CPU bound 上幾乎無用，但 I/O bound 仍有效。Python 3.13 free-threading 是轉折點。

POSIX pthreads, Java Threads, Python threading. Each thread is an OS scheduling unit; shared memory requires mutexes/semaphores. Pitfalls: deadlocks, races, priority inversion. Python's GIL makes threads useless for CPU-bound work, but they still help for I/O. Python 3.13 free-threading is a turning point.

② Async / await（事件迴圈）

Python asyncio / JS / Rust tokio / C# Task。單 thread 上跑多個 coroutine，I/O wait 時切換。對網路服務、爬蟲、API gateway 極適合，可同時處理 10K+ 連線。但 CPU bound 完全幫不上忙——還是要 process pool。

Python asyncio, JS, Rust tokio, C# Task. Multiple coroutines on one thread, swapped at I/O waits. Perfect for network services, scrapers, API gateways — 10k+ connections at once. Useless for CPU-bound work — use a process pool.

③ Actor 模型（訊息傳遞）

Erlang / Elixir / Akka / Pony。每個 actor 有獨立 state，只能透過訊息溝通——無共享記憶體 = 無 race。WhatsApp 在 Erlang 上用 200 萬連線/單機。Erlang 的「let it crash」哲學影響了現代 microservices。

Erlang / Elixir / Akka / Pony. Each actor has private state, communicates only via messages — no shared memory = no races. WhatsApp ran 2M connections per box on Erlang. The "let it crash" philosophy shaped modern microservices.

④ CSP（Go channels）

Tony Hoare 1978 提出 CSP，Go 的 goroutine + channel 是最成功的實作。輕量 thread（2KB stack）+ typed channel 通訊。"Don't communicate by sharing memory; share memory by communicating." 是 Go 名言。Kubernetes、Docker、Prometheus、CockroachDB 都用此模型。

Tony Hoare 1978 invented CSP; Go's goroutines + channels are the most successful implementation. Lightweight threads (2 KB stack) + typed channels. "Don't communicate by sharing memory; share memory by communicating" — Go's motto. Kubernetes, Docker, Prometheus, CockroachDB all use this model.

🎯
生資對應：BLAST、BWA、STAR 多用 OS thread + OpenMP；長 read 流式工具用 async；nf-core 在 Nextflow 內部用 actor-like dataflow（每個 process 是一個 actor，靠 channel 串接）。知道你的工具用哪種模型，能更好調 thread/memory 參數。
Bioinformatics mapping: BLAST/BWA/STAR use OS threads + OpenMP; long-read streaming tools use async; nf-core uses actor-like dataflow inside Nextflow (each process is an actor, wired via channels). Knowing your tool's model helps you tune threads and memory.
2026 Python 工具鏈革命

九-D、2026 Python 工具鏈大革命

2024-2026 期間，Python 工具鏈經歷了 30 年來最大變革——由舊金山新創 Astral（Charlie Marsh 創辦）一波接一波推出 Rust 寫的新工具，全部 10-100× 快過原版：

  • ruff (2022)：取代 flake8 + isort + pylint + autoflake + pydocstyle……一個工具搞定，比 flake8 100× 快。Pandas、FastAPI、HuggingFace 全部換上。
  • uv (2024)：取代 pip + pip-tools + virtualenv + pipx + poetry + pyenv。lockfile 速度 10-100× 快過 poetry。可一鍵裝 Python 版本（內建 python-build-standalone）。2026 年 uv 已成事實標準，連官方 docs 都推薦。
  • ty (2025)：取代 mypy + pyright，是 type checker 的下一代。比 mypy 100× 快，支援 PEP 695 新泛型語法、增量檢查。
  • rye → uv 合併 (2024-09)：Armin Ronacher 把 rye 捐給 Astral，並入 uv。

對生資的影響：① Snakemake / Nextflow 都已加入 uv 支援；② Bioconductor 雖在 R 端，但 reticulate 後端 Python env 也建議用 uv；③ 上 cluster 安裝環境從 30 分鐘變 30 秒；④ Conda/Bioconda 在 2026 仍是 bioinformatics 主流，但個人 Python 開發已大量轉向 uv。

From 2024 to 2026, Python tooling saw its biggest shake-up in 30 years, driven by SF startup Astral (Charlie Marsh) shipping Rust-based tools 10-100× faster than originals:

  • ruff (2022): replaces flake8 + isort + pylint + autoflake + pydocstyle — one tool, 100× faster than flake8. Adopted by pandas, FastAPI, HuggingFace.
  • uv (2024): replaces pip + pip-tools + virtualenv + pipx + poetry + pyenv. Lockfiles 10-100× faster than poetry. Installs Python versions in one command (bundles python-build-standalone). By 2026 uv is the de facto standard; official docs recommend it.
  • ty (2025): replaces mypy + pyright. Next-gen type checker, 100× faster than mypy; supports PEP 695 generics, incremental checking.
  • rye → uv merger (Sep 2024): Armin Ronacher donated rye to Astral, merged into uv.

Bioinformatics impact: (1) Snakemake/Nextflow added uv support; (2) Bioconductor stays on R but reticulate's Python backend benefits; (3) cluster env install drops from 30 min to 30 sec; (4) Conda/Bioconda remains the bio mainstream in 2026, but personal Python dev has moved heavily to uv.
