電腦網路

從家裡的 Wi-Fi 路由器到全球 Internet，本章帶你穿越 OSI 七層、TCP/IP、HTTP/3、IPv6 與 5G/Wi-Fi 7 的 2026 全貌。

From a home Wi-Fi router to the global Internet — traverse the OSI 7 layers, TCP/IP, HTTP/3, IPv6, and the 2026 landscape of 5G and Wi-Fi 7.

概覽

網路：把每台機器串起來

1969 年 ARPANET 把 4 台電腦連起來；2026 年全球已有 180 億個聯網裝置——手機、PC、IoT 感測器、汽車、家電。要讓不同廠商的硬體、不同 OS、不同程式能彼此溝通，必須有共同的「協定 (protocol)」。

網路工程把通訊難題分層解決：每一層只負責一件事，上層使用下層提供的服務。這就是 OSI 七層模型與 TCP/IP 四層模型的精神。

In 1969 ARPANET linked 4 computers; in 2026 there are 18 billion connected devices — phones, PCs, IoT sensors, cars, appliances. To let different vendors, OSes, and apps talk to each other, we need shared protocols.

Networking breaks the problem into layers: each layer does one job and uses the services of the layer below. That's the spirit of the OSI 7-layer and TCP/IP 4-layer models.

💡
核心觀念：網路是「分層的抽象」。你的瀏覽器只需呼叫 HTTP，不需要知道 TCP 怎麼握手、IP 怎麼路由、Wi-Fi 怎麼調變射頻——每一層各司其職。 Core idea: Networking is layered abstraction. Your browser calls HTTP without knowing how TCP handshakes, how IP routes, or how Wi-Fi modulates RF — each layer has its own job.

IP 位址

二、IPv4 vs IPv6

每台聯網裝置都需要一個唯一的 IP 位址。1981 年定義的 IPv4 用 32 bit，最多 ~43 億個位址——已於 2011 年用盡 (IANA)。IPv6 (1998) 用 128 bit，提供 3.4 × 10³⁸ 個位址（地球每平方公分可分到 10²⁸ 個）。

2026 年實況：Google 統計，全球約 45% 的使用者已透過 IPv6 連線，行動網路採用率更高 (~70%)。

Every connected device needs a unique IP address. IPv4 (1981) uses 32 bits — about 4.3 billion addresses, exhausted by IANA in 2011. IPv6 (1998) uses 128 bits — 3.4 × 10³⁸ addresses (10²⁸ per square centimeter of Earth).

2026 reality: per Google, ~45% of users reach Google over IPv6 globally; mobile networks are even higher (~70%).

輔助協定：DNS（網域名稱 → IP，如 www.google.com → 142.250.x.x）、ARP（IP → MAC，同網段）、DHCP（自動發位址）、ICMP（ping、traceroute）、NAT（多台內網裝置共用 1 個公網 IP）、CIDR（位址聚合，10.0.0.0/8 表前 8 bit 為網路號）。

Helper protocols: DNS (name → IP), ARP (IP → MAC, local segment), DHCP (auto-assign address), ICMP (ping, traceroute), NAT (many private IPs sharing one public IP), CIDR (10.0.0.0/8 means first 8 bits are the network part).

TCP 三向交握 (3-way handshake)：

  1. Client → Server: SYN (seq=x)
  2. Server → Client: SYN-ACK (seq=y, ack=x+1)
  3. Client → Server: ACK (ack=y+1) → 連線建立

TCP 3-way handshake:

  1. Client → Server: SYN (seq=x)
  2. Server → Client: SYN-ACK (seq=y, ack=x+1)
  3. Client → Server: ACK (ack=y+1) → connection established

協定選擇

五、協定決策樹

🌳 該選 TCP 還是 UDP？

Q1:
遺失一個封包會造成「資料毀損」？→ 是 → TCP（檔案、網頁、SSH）。
Q2:
需要「低延遲、即時性」（晚到不如不到）？→ 是 → UDP（VoIP、線上遊戲、即時影像）。
Q3:
想要 TCP 的可靠性 + UDP 的速度？→ 用 QUIC / HTTP/3（建立在 UDP 上，自帶可靠性、加密）。
Q4:
多個請求並行載入（大量小檔）？→ 用 HTTP/2 或 HTTP/3（多工複用，避免 head-of-line blocking）。
Q1:
Would a lost packet corrupt the data? → Yes → TCP (files, web, SSH).
Q2:
Need ultra-low latency (late = useless)? → Yes → UDP (VoIP, games, live video).
Q3:
Want TCP reliability + UDP speed? → Use QUIC / HTTP/3 (on UDP, with reliability and encryption built-in).
Q4:
Many parallel requests (lots of small assets)? → HTTP/2 or HTTP/3 — multiplexing avoids head-of-line blocking.
無線與最新趨勢

六、無線網路與 2026 趨勢

📶 Wi-Fi 7 (802.11be)

2024 正式批准，理論峰值 46 Gbps。新功能：320 MHz 通道、多鏈路操作 (MLO)、4096-QAM。

Ratified 2024, theoretical peak 46 Gbps. New features: 320 MHz channels, Multi-Link Operation (MLO), 4096-QAM.

📱 5G / 6G

5G 商用密度已過 60%。6G 規格化進行中 (3GPP Release 21+, 預計 2030 商用)，目標 1 Tbps、亞毫秒延遲。

5G is in >60% of regions. 6G is being standardized (3GPP Rel 21+, ~2030 launch) — targeting 1 Tbps and sub-ms latency.

🚀 HTTP/3 + QUIC

2026 全球流量約 35% 為 HTTP/3。Google、Cloudflare、Meta 主導推動；TLS 1.3 內建。

~35% of global web traffic in 2026. Driven by Google, Cloudflare, Meta. TLS 1.3 built-in.

🔒 HTTPS = HTTP + TLS 1.3

2026 全球 95%+ 網頁使用 HTTPS；TLS 1.3 (RFC 8446) 將握手從 2-RTT 縮減為 1-RTT，更安全更快。

95%+ of web pages use HTTPS in 2026; TLS 1.3 (RFC 8446) cuts the handshake from 2-RTT to 1-RTT — safer and faster.

🔵 Bluetooth 5.x

低功耗 BLE 主導 IoT；Bluetooth 5.3 提升通道分類、降低干擾；6.0 標準 2025 公布。

BLE dominates IoT. Bluetooth 5.3 improves channel classification; 6.0 was published in 2025.

🛰️ 衛星網路

Starlink、Amazon Kuiper 部署 LEO 衛星群，提供偏遠地區 100+ Mbps、~30ms 延遲。

Starlink, Amazon Kuiper deploy LEO constellations — 100+ Mbps and ~30ms latency in remote areas.

    client.send(Packet(SYN=true, seq=x))
    // 2. Server 回 SYN-ACK
    server.send(Packet(SYN=true, ACK=true, seq=y, ack=x+1))
    // 3. Client 回 ACK

    return "ESTABLISHED"
