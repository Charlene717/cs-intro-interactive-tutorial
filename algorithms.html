演算法與複雜度

演算法是「能解決問題的有限步驟」。寫得對只是起點，寫得快才是工程。本章帶你看懂 Big-O 與經典演算法。

An algorithm is a finite sequence of steps that solves a problem. Writing correct code is just the start — writing fast code is engineering. This chapter unpacks Big-O and the classics.

概覽

為何複雜度比語言更重要？

同一個問題，用 C 寫的 O(n²) 演算法在 100 萬筆資料上可能跑 30 分鐘；換成 Python 寫的 O(n log n) 演算法卻只要 3 秒。選對演算法的提速，遠大於選對語言或硬體升級。

Knuth 給出演算法的五項條件：① 輸入 (input)；② 輸出 (output)；③ 有限性 (finiteness：一定要停)；④ 確定性 (definiteness：每一步明確)；⑤ 有效性 (effectiveness：每步可在有限時間執行)。

For 1M records, an O(n²) algorithm in C may take 30 minutes — while an O(n log n) algorithm in Python finishes in 3 seconds. Picking the right algorithm beats picking the right language or upgrading hardware.

Knuth's five properties of an algorithm: (1) input, (2) output, (3) finiteness (must terminate), (4) definiteness (each step unambiguous), (5) effectiveness (each step executable in finite time).

💡
核心觀念：Big-O 描述「輸入大小 n 趨於無窮時，執行時間的增長等級」。常數、低階項、係數通通忽略——只看「長相」。 Core idea: Big-O describes the growth rate of running time as input size n approaches infinity. Constants, lower-order terms, and coefficients are dropped — only the dominant term matters.

搜尋演算法

四、搜尋演算法

🔍 Linear Search — O(n)

從頭找到尾。最簡單、適用於小資料或未排序資料。1000 筆資料平均要看 500 次。

Scan from start to end. Simple; fine for small or unsorted data. On 1000 items, ~500 checks on average.

⚖️ Binary Search — O(log n)

每次砍一半，但要求陣列已排序。100 萬筆只需 20 次比較。

Halve the search space each step, but requires sorted input. ~20 comparisons for 1M items.

🪣 Hash Lookup — O(1)

透過 hash function 直接定位。理想情況常數時間，但需要記憶體與良好的 hash 函式來避免碰撞。

Hash function maps key directly to a bucket. Constant time on average, at the cost of memory and a good hash to avoid collisions.

設計典範

五、五大設計典範

Brute Force

逐一列舉所有可能。簡單但常常爆炸性慢，適用於小規模或當作正確性基準。

Try every possibility. Simple but often explodes; useful for small inputs or as a correctness baseline.

Divide & Conquer

把問題切成更小的子問題，遞迴解決後合併。Merge Sort、Quick Sort、FFT、Karatsuba 乘法都是經典。

Split into subproblems, recurse, combine. Classics: merge sort, quick sort, FFT, Karatsuba multiplication.

Greedy

每一步都做「當下最佳」的選擇。Dijkstra 最短路徑、Huffman 編碼、零錢找零（某些幣制）是典型成功例。

Make the locally best choice at each step. Dijkstra's shortest path, Huffman coding, certain coin-change problems are classic successes.

Dynamic Programming

把重複子問題的結果「記下來」(memoization)。Fibonacci、0/1 Knapsack、編輯距離、最長公共子序列都是 DP 經典。

Memoize results of overlapping subproblems. Fibonacci, 0/1 Knapsack, edit distance, LCS are classic DP problems.

Backtracking

嘗試 → 失敗 → 退一步再試。八皇后、數獨、迷宮、N-queens 都是經典案例。

Try, fail, back up, try again. N-queens, sudoku, mazes are classic backtracking problems.

Q1:
Use the language's built-in? → Yes → Just call sort() (Python/Java use Tim Sort; C++ uses Introsort) — enough for 99% of cases.
Q2:
Very small (n ≤ 20)? → Yes → Insertion Sort: tiny constants, easy to write.
Q3:
Need stability? → Yes → Merge Sort or Tim Sort. Avoid Quick Sort.
Q4:
Extremely memory-tight? → Yes → Heap Sort: in-place O(1) extra, guaranteed O(n log n).
Q5:
Bounded integers? → Yes → Counting / Radix Sort can hit O(n).
程式碼

七、Merge / Quick Sort 實作

# Merge Sort：分而治之，O(n log n)、stable / Divide-and-conquer, O(n log n), stable
def merge_sort(arr: list) -> list:
    if len(arr) <= 1:
        return arr
    mid = len(arr) // 2
    left  = merge_sort(arr[:mid])      # 遞迴排左半
    right = merge_sort(arr[mid:])      # 遞迴排右半
    return merge(left, right)             # 合併兩個有序串列

def merge(a, b):
    result, i, j = [], 0, 0
    while i < len(a) and j < len(b):
        if a[i] <= b[j]:
            result.append(a[i]); i += 1
        else:
            result.append(b[j]); j += 1
    result.extend(a[i:]); result.extend(b[j:])
    return result

print(merge_sort([5,2,8,1,9,3]))   # [1, 2, 3, 5, 8, 9]
// Quick Sort：分而治之，平均 O(n log n)，最差 O(n²)
function QuickSort(arr, lo, hi):
    if lo < hi:
        let p = Partition(arr, lo, hi)
        QuickSort(arr, lo, p − 1)
        QuickSort(arr, p + 1, hi)

function Partition(arr, lo, hi):
    let pivot = arr[hi]
    let i = lo − 1
    for j from lo to hi − 1:
        if arr[j] <= pivot:
            i = i + 1
            SWAP(arr[i], arr[j])
    SWAP(arr[i + 1], arr[hi])
    return i + 1
