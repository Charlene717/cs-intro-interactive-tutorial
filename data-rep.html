資料表示法

電腦的世界只有 0 和 1。本章告訴你：為什麼 0.1 + 0.2 ≠ 0.3 害一枚火箭爆炸、為什麼 Excel 強迫 27 個基因改名，以及 FASTQ Phred 質量分數背後隱藏的 ASCII 故事。

A computer sees only 0s and 1s. This chapter shows why 0.1 + 0.2 ≠ 0.3 blew up a rocket, why Excel forced 27 genes to be renamed, and the ASCII story hiding inside every FASTQ Phred score.

1996.06.04, 09:34 UTC

一、$5 億美元的整數溢位

1996 年 6 月 4 日，歐洲太空總署 ESA 的阿麗亞娜 5 號火箭首次飛行。發射 37 秒後，火箭突然偏離航道，自毀系統啟動——損失 5 億美元的衛星貨物與 80 億美元的研發費用，這是史上最昂貴的軟體 bug 之一。

事後調查（ESA-CNES 1996 報告）發現災難原因竟是一行型別轉換的程式碼：阿麗亞娜 4 號的慣性導航系統把「水平速度」儲存為 64-bit float，新版火箭速度更快，數值超過了 32,768（2¹⁵）；當系統把它轉成 16-bit signed int 時，發生溢位、產生負值，導航電腦以為火箭翻覆，緊急修正導致氣動應力過大解體。

核心教訓：「位元有限，數字無限」。理解計算機如何用有限位元表達各種資料，是寫出正確程式的第一性原理。

4 June 1996. ESA's Ariane 5 rocket lifted off on its maiden flight. 37 seconds later it veered off course and self-destructed — losing $500 million in cargo and $8 billion in R&D. One of the most expensive software bugs in history.

The post-mortem (ESA-CNES 1996) found a single type-conversion line at fault: Ariane 4's inertial unit stored horizontal velocity as a 64-bit float; Ariane 5 was faster, exceeding 32,768 (2¹⁵); converting to 16-bit signed int overflowed to a negative, the nav computer believed the rocket had flipped, and the corrective steering tore it apart.

The lesson: "bits are finite, numbers are infinite." Knowing how computers encode data with finite bits is the first principle of writing correct programs.

💡
核心觀念：位元組裡的二進位「沒有自帶意義」。同一個 byte 01000001 可被解讀為整數 65、字元 'A'、RGB 中的紅色分量、FASTQ 的 Phred 32——取決於程式上下文。 Core idea: Bits have no inherent meaning. The byte 01000001 can be integer 65, the letter 'A', a red-channel value, or FASTQ Phred 32 — it depends entirely on program context.
bit / byte / 進位制

二、bit、byte 與進位制

電子元件最容易表達兩種狀態：高電壓/低電壓、磁化 N/S、光點反射/不反射。把兩種狀態指定為 0 與 1，就是一個 bit (binary digit)。8 個 bit = 1 個 byte，可表達 256 種值 (0–255)。所有更高層次的資料——整數、實數、文字、圖片、AI 模型權重——都只是「許多 bit 的不同詮釋」。

Electronic devices easily store two states: high/low voltage, magnetized N/S, light reflected/not. Call those 0 and 1 and you have a bit (binary digit). 8 bits = 1 byte, representing 256 values (0–255). All higher-level data — ints, floats, text, images, AI weights — is just "many bits, interpreted differently."

🔢 二進位

只用 0 和 1。每位代表 2 的次方。1011₂ = 8+0+2+1 = 11。電腦底層的母語。

Just 0 and 1. Each digit is a power of 2. 1011₂ = 8+0+2+1 = 11. The native tongue of every computer.

🔟 十進位

人類日常使用，0–9。2026₁₀ = 2·10³+0·10²+2·10+6。源於十個手指。

Everyday human counting, 0–9. 2026₁₀ = 2·10³+0·10²+2·10+6. Origin: ten fingers.

🔡 十六進位

0–9, A–F。一個 hex digit = 4 個 bit，所以 1 個 byte = 2 個 hex chars。用於 #FF8C00 顏色、MAC 位址、記憶體 dump。

0–9, A–F. One hex digit = 4 bits, so 1 byte = 2 hex chars. Used for #FF8C00 colors, MAC addresses, memory dumps.

負數與補數

四、二補數

整數需要表示負數。最流行的方案是 二補數 (two's complement)，因為它讓加法器同時處理正負——硬體最簡單。

二補數規則：① 取絕對值的二進位；② 全部位元反轉 (0↔1)；③ 加 1。

範例 (8 bit)： +5 = 0000 0101，所以 −5 = 1111 1011（反轉得 1111 1010，再加 1）。最左邊一位為「符號位」：0 正、1 負。

To represent negatives, the universal scheme is two's complement: one adder handles both signs.

Rule: (1) take absolute value in binary; (2) flip every bit; (3) add 1.

Example (8 bit): +5 = 0000 0101, so −5 = 1111 1011 (flip → 1111 1010, +1). Leftmost bit = sign: 0 positive, 1 negative.

Integer overflow: A 32-bit signed int caps at 2,147,483,647. +1 wraps to −2,147,483,648 — the root cause of the 1996 Ariane 5 explosion and of PSY's "Gangnam Style" breaking YouTube's 32-bit view counter in 2014. YouTube has since upgraded to 64-bit.
IEEE 754 拆解

五、IEEE 754 浮點數

要表達 3.14159 這種實數，使用 IEEE 754（1985 制定，2008/2019 修訂）。每個數字拆成三部分：

(−1)s × 1.M × 2(E − bias)

  • s（符號位 sign）：1 bit，0 正 1 負
  • E（指數 exponent）：8 bit (FP32) / 11 bit (FP64)，須減 bias (127 / 1023)
  • M（尾數 mantissa/significand）：23 bit (FP32) / 52 bit (FP64)，前面隱含一個 1

還有兩個特殊「非數值」：NaN (Not a Number，例如 0/0、sqrt(-1)) 與 Inf (溢位)。NaN 的怪癖：NaN ≠ NaN！要檢查只能用 isnan(x)，這是 IEEE 754 為了讓「污染傳播」設計的——任何含 NaN 的運算結果都是 NaN，提醒程式員出錯了。

還有 subnormal（非正規）數：當指數為 0 時，隱含的前導 1 變 0，可表達極小數（FP32 可到 1.4 × 10⁻⁴⁵）。代價是 CPU 處理 subnormal 比 normal 慢 10–100 倍——一些 deep learning 框架會故意「flush-to-zero」避開。

For reals like 3.14159, use IEEE 754 (1985, revised 2008/2019). Each number = three parts:

(−1)s × 1.M × 2(E − bias)

  • s (sign): 1 bit, 0 = positive, 1 = negative
  • E (exponent): 8 bits (FP32) / 11 bits (FP64), subtract bias (127 / 1023)
  • M (mantissa): 23 bits (FP32) / 52 bits (FP64), with implicit leading 1

Two special values: NaN (0/0, sqrt(-1)) and Inf (overflow). NaN quirk: NaN ≠ NaN. You must use isnan(x). IEEE 754 designed it this way so NaN propagates through computations — flagging that something went wrong.

Also: subnormal numbers fill the gap near zero (FP32 down to 1.4 × 10⁻⁴⁵), but CPUs process them 10–100× slower than normals. Many deep-learning frameworks "flush-to-zero" to skip them.

🚨
經典陷阱：在 Python 試試 0.1 + 0.2 = 0.30000000000000004，不等於 0.3！因為 0.1 在二進位是無窮循環小數（類似 1/3 在十進位是 0.333...）。金融計算絕不要用浮點數——用 decimal.Decimal 或整數「分」為單位。1991 年波斯灣戰爭中，美軍 Patriot 飛彈防禦系統因浮點累積誤差（時鐘計時 100 小時後誤差 0.34 秒）攔截失敗，造成 28 名美軍死亡。
Classic gotcha: In Python, 0.1 + 0.2 = 0.30000000000000004 — not 0.3. 0.1 is an infinite repeating fraction in binary (like 1/3 in decimal). Never use floats for money — use decimal.Decimal or integer cents. In the 1991 Gulf War, the Patriot missile defense failed an interception due to accumulated float drift (0.34 s drift after 100 hours), killing 28 U.S. soldiers.
四個必聽災難

六、四個經典災難

📅 Y2K 千禧蟲

1960–80 年代記憶體昂貴，COBOL 程式員把年份存成 2 位數（"99" 代表 1999）。1999 年大家恐慌：2000 年系統會以為是 1900 年？銀行利息算錯？全球花了 $3,000–6,000 億美元修補。結果意外地平靜——但這是史上最大規模的軟體修補工程。

In the 1960s–80s, memory was expensive, so COBOL programmers stored years as 2 digits ("99" = 1999). In 1999 the world panicked: would systems read 2000 as 1900? Banks miscalculate interest? Global remediation cost $300–600 billion. The actual transition was eerily smooth — the largest software fix in history.

⏰ 2038 問題

Unix 系統用 32-bit signed int 儲存「從 1970-01-01 起的秒數」。2038-01-19 03:14:07 UTC會溢位變負——衣物、空調、舊嵌入式設備可能集體當機。Linux 5.6 已切換到 64-bit time_t，但全球仍有億萬台 32-bit 設備需要更新。

Unix stores "seconds since 1970-01-01" as 32-bit signed int. On 2038-01-19 03:14:07 UTC, it overflows to negative — washers, ACs, legacy embedded gear could die en masse. Linux 5.6+ switched to 64-bit time_t, but billions of 32-bit devices remain.

🧬 Excel 改基因名

研究發現 (Ziemann 2016 Genome Biol)：20% 的基因組相關論文補充表格含 Excel 自動轉換錯誤！基因 MARCH1 被改成「3 月 1 日」、SEPT2 變「9 月 2 日」、DEC1 變「12 月 1 日」。問題嚴重到 2020 年 HGNC (Bruford 2020 Nat Genet) 被迫正式將 27 個基因改名：MARCH1 → MARCHF1、SEPT1 → SEPTIN1。

A study (Ziemann 2016 Genome Biol) found 20% of papers with genomics supplements contained Excel auto-conversion errors! Gene MARCH1 became "1 March," SEPT2 became "2 Sept," DEC1 became "1 Dec." So severe that in 2020 (Bruford 2020 Nat Genet), HGNC officially renamed 27 genes: MARCH1 → MARCHF1, SEPT1 → SEPTIN1.

🚀 Patriot 飛彈誤差

1991 年波斯灣戰爭，美軍 Patriot 防禦系統用 24-bit 浮點數計算時鐘（每 0.1 秒一個 tick）。0.1 在二進位是無窮循環，每 tick 累積 9.5 × 10⁻⁸ 秒的誤差。連續運行 100 小時後誤差達 0.34 秒，導致無法精準預測來襲 Scud 飛彈的位置——攔截失敗，沙烏地兵營 28 名美軍陣亡。GAO 1992 報告至今是浮點誤差的教科書案例。

In the 1991 Gulf War, a U.S. Patriot battery's clock used a 24-bit float, ticking every 0.1 s. Since 0.1 is infinite-repeating in binary, each tick drifted 9.5 × 10⁻⁸ s. After 100 hours, drift hit 0.34 s — too imprecise to predict an incoming Scud. The interception failed; 28 soldiers died at Dhahran barracks. GAO's 1992 report remains the textbook example of float drift.

ASCII → Unicode → UTF-8

七、文字編碼演化

ASCII (1963)

7 bit 編碼，表達 128 個英文字母、數字、標點與控制字元。'A' = 65、'a' = 97、'0' = 48、' ' = 32。優點簡單；缺點不支援其他語言。為何只到 127？因為早期電報用 7 bit 加一個 parity bit 偵錯，加起來剛好 1 byte。

7-bit encoding for 128 chars: letters, digits, punctuation, control codes. 'A' = 65, 'a' = 97, '0' = 48, ' ' = 32. Simple but English-only. Why 127? Early teleprinters used 7 bits plus a parity bit = 1 byte total.

Big5 / GB2312 / Shift-JIS (1980s)

各國各自發展中日韓編碼。同一個 byte 在不同編碼下意義不同 → 出現「亂碼 (mojibake)」災難。檔案沒附編碼資訊時，幾乎無法復原。

Each region built its own encoding (zh-TW Big5, zh-CN GB2312, Japan Shift-JIS). The same bytes meant different things → the "mojibake" disaster. Files without encoding metadata are nearly impossible to recover.

Unicode (1991)

給世界上每個字元一個唯一的「碼點 (code point)」。例如 U+4E2D = 「中」、U+1F600 = 😀。2026 年已收錄 14.9 萬+ 字元。Unicode 只是「身分證」，不是儲存格式——還需要另一層編碼把碼點變成 bytes。

Assigns every character in the world a unique code point: U+4E2D = 「中」, U+1F600 = 😀. Over 149,000 chars in 2026. Unicode is the "ID," not a storage format — you still need an encoding to turn code points into bytes.

UTF-8 (1992) ⭐

Ken Thompson & Rob Pike 在 1992 年於紐澤西小餐館的餐墊上發明 UTF-8：把 Unicode 碼點變成 1–4 個 byte。英文 1 byte（ASCII 完全相容）、歐洲拉丁字母 2 byte、中文 3 byte、emoji 4 byte。2026 年 98%+ 網頁使用 UTF-8，是事實上的網路標準。

Ken Thompson & Rob Pike invented UTF-8 on a New Jersey diner placemat in 1992: encode Unicode as 1–4 bytes. English 1 byte (ASCII compatible), European Latin 2 bytes, Chinese 3 bytes, emoji 4 bytes. 98%+ of web pages use UTF-8 in 2026 — the de facto internet standard.

給生資人

九、🧬 給生物資訊學家

🧬
給生物資訊學家：FASTQ、BAM、Excel 全是資料表示問題

你今天接觸的 FASTQ、BAM、VCF、CRAM 全部都是「位元的不同詮釋」。理解 ASCII、二進位、浮點數，能讓你避免改錯基因名、誤判 Phred 質量、被 BAM/CRAM 邊界 bug 困住。

FASTQ, BAM, VCF, CRAM — all you handle daily — are just "different interpretations of bits." Understanding ASCII, binary, and floats helps you avoid renaming genes wrong, misreading Phred scores, and getting stuck on BAM/CRAM boundary bugs.

📊 FASTQ Phred 編碼

FASTQ 第四行每個字元代表一個鹼基的質量分數 (Q)：Q = -10·log₁₀(P_error)。Q30 = 99.9% 正確；Q40 = 99.99% 正確。但 Q 怎麼存？用 ASCII！Sanger / Illumina 1.8+：char = Q + 33（'!' 開始）；Illumina 1.3–1.7：char = Q + 64（'@' 開始）。所以 'I' (ASCII 73) = Q40。編碼搞混會導致整份 trimming 結果錯誤！

The 4th line of every FASTQ record encodes per-base quality (Q): Q = -10·log₁₀(P_error). Q30 = 99.9% accurate, Q40 = 99.99%. How is Q stored? As ASCII! Sanger / Illumina 1.8+: char = Q + 33 (starts at '!'); Illumina 1.3–1.7: char = Q + 64 (starts at '@'). So 'I' (ASCII 73) = Q40. Misreading the offset corrupts every trimming result.

💾 BAM/CRAM 二進位

FASTQ/SAM 是純文字 (ASCII)，人類可讀但每個鹼基要 1 byte (A/C/G/T)。BAM 是 SAM 的二進位壓縮版：每鹼基只用 4 bit (2¹⁶ 種組合) + bgzip 壓縮，空間省 ~5–10 倍，隨機存取也快。CRAM 更進一步——只儲存與參考序列不同處的差異，再省 30–60%。每 100 TB 的 BAM 用 CRAM 可省 50 TB 儲存費。

FASTQ/SAM are plain text (ASCII): readable but 1 byte per base (A/C/G/T). BAM is SAM's binary compressed sibling: 4 bits per base (2¹⁶ combos) + bgzip, ~5–10× smaller, with random access. CRAM goes further — stores only differences from a reference, saving another 30–60%. On a 100 TB BAM archive, CRAM saves 50 TB of storage cost.

📅 Excel 與 HGNC 改名

Excel 的自動「智能」轉換把 MARCH1 變「3 月 1 日」、SEPT2 變「9 月 2 日」、2310009E13 變「2.31E+13」科學記號。Ziemann 2016 (Genome Biol) 發現 20% 的基因組學論文表格都受影響。HGNC 終於投降——2020 年 (Bruford 2020 Nat Genet) 正式將 27 個基因改名避開 Excel：MARCH1 → MARCHF1、SEPT1 → SEPTIN1。啟示：用 TSV 而非 Excel，或在 Excel 中將欄位先設為「文字」格式。

Excel's auto-conversion turns MARCH1 into "1 March," SEPT2 into "2 Sept," 2310009E13 into scientific notation "2.31E+13." Ziemann 2016 (Genome Biol) found 20% of genomics-paper supplements were affected. HGNC finally surrendered — in 2020 (Bruford 2020 Nat Genet) it officially renamed 27 genes to evade Excel: MARCH1 → MARCHF1, SEPT1 → SEPTIN1. Lesson: use TSV, not Excel — or pre-format columns as "Text."

🎯 FP8 / BF16 改變了生資 AI

2020 年起 NVIDIA A100 引入 BF16 / FP8，AlphaFold2、ESM-2、scGPT 都在這些低精度格式下訓練：BF16 比 FP32 記憶體省一半、運算快 2× 而精度幾乎無損（指數位元數一樣為 8）。FP8 推論能再快 2×。沒有 BF16 / FP8，今天的生物大模型根本訓練不起。

Since 2020, NVIDIA A100 introduced BF16/FP8; AlphaFold2, ESM-2, scGPT all train in these low-precision formats. BF16 halves memory and doubles math vs FP32 with negligible accuracy loss (same 8-bit exponent). FP8 doubles inference again. Without BF16/FP8, today's biological large models would be untrainable.

Storing Unix timestamps? → Yes → Use int64 to avoid the 2038 overflow.
Q7:
Storing DNA sequences? → Yes → Text use FASTA/FASTQ; analysis use 2-bit packed (4 bp = 1 byte) or BAM/CRAM directly.

// 十進位轉二進位（除 2 取餘法）/ Decimal → binary by repeated division
function DecToBin(n):
    if n == 0: return "0"
    let bits = ""
    while n > 0:
        bits = (n mod 2) + bits      // prepend remainder
        n = n ÷ 2                    // integer division
    return bits

// 二補數（將正數轉為其 n-bit 負數）/ Two's complement
function TwosComp(value, n_bits):
    let mask = 2^n_bits − 1
    return ((NOT value) + 1) AND mask

// IEEE 754 拆解 / Decompose IEEE 754 FP32
function DecomposeFP32(x):
    let bits = reinterpret_as_uint32(x)
    let sign     = (bits >> 31) AND 1
    let exponent = (bits >> 23) AND 0xFF
    let mantissa = bits AND 0x7FFFFF
    return (sign, exponent, mantissa)
五個常見誤解

十二、常見誤解

🚨
誤解 #1：「float 可以精確表示 0.1」——錯。0.1 在二進位是無窮循環小數，IEEE 754 必須截斷。0.1 + 0.2 = 0.30000000000000004。要比較浮點數請用 math.isclose() 或設定容忍度。
Myth #1: "Float exactly represents 0.1." Wrong. 0.1 is an infinite repeating fraction in binary; IEEE 754 must truncate. 0.1 + 0.2 = 0.30000000000000004. Compare floats with math.isclose() or a tolerance.
🚨
誤解 #2：「Unicode 就是 UTF-8」——錯。Unicode 是抽象的碼點對照表（U+4E2D = 中），UTF-8/UTF-16/UTF-32 才是把碼點變 bytes 的編碼。Python 3 字串內部是 Unicode；存檔/網路傳輸時才轉成 UTF-8 bytes。
Myth #2: "Unicode is UTF-8." Wrong. Unicode is the abstract code-point catalog (U+4E2D = 中); UTF-8/UTF-16/UTF-32 are encodings that turn code points into bytes. Python 3 strings are Unicode internally; files/networks use UTF-8 bytes.
⚠️
誤解 #3：「char 永遠是 1 byte」——只在 ASCII 內。UTF-8 中文 3 byte、emoji 4 byte。len("中文") 在 Python 3 是 2（字元數），但 len("中文".encode()) 是 6（byte 數）。處理 FASTA header 包含特殊字元時要特別注意。
Myth #3: "A char is always 1 byte." Only in ASCII. In UTF-8, Chinese = 3 bytes, emoji = 4 bytes. In Python 3, len("中文") = 2 (chars) but len("中文".encode()) = 6 (bytes). Beware when handling FASTA headers with special chars.
⚠️
誤解 #4：「FASTQ 質量字元的 ASCII 編碼是固定的」——錯。Sanger / Illumina 1.8+ 用 Q+33，舊 Illumina 1.3–1.7 用 Q+64。把 Phred+64 當 Phred+33 解碼會讓 Q40 變成 Q9——整份 QC 全錯。fastp / seqkit 都有自動偵測。
Myth #4: "FASTQ Phred ASCII encoding is fixed." Wrong. Sanger / Illumina 1.8+ uses Q+33; old Illumina 1.3–1.7 uses Q+64. Reading Phred+64 as Phred+33 turns Q40 into Q9 — all QC is wrong. fastp / seqkit auto-detect.
⚠️
誤解 #5：「FP16 / BF16 必定不夠精準」——錯。AlphaFold2、ESM-2、scGPT、GPT-4 都用 BF16 訓練，且結果不比 FP32 差。秘訣是 BF16 的指數範圍與 FP32 相同（都 8 bit），只是尾數較少——適合 NN 梯度的「動態範圍 > 精度」需求。
Myth #5: "FP16/BF16 are always too imprecise." Wrong. AlphaFold2, ESM-2, scGPT, GPT-4 all train in BF16 with no loss vs FP32. Trick: BF16's exponent range matches FP32 (8 bits), only the mantissa shrinks — perfect for NN gradients where dynamic range matters more than precision.
